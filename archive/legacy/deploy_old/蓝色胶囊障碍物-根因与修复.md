# 蓝色胶囊状障碍物 —— 根因与修复

> 现象：场景里凭空多出一个蓝色胶囊状障碍物，人能直接穿过去，机器人识别不到它，每次都会撞上。
> 结论：**它不是障碍物，是「人」掉了半个身子。**

---

## 1. 它到底是什么

`work_area.sdf` 里 `<model name="person">` 一共 5 个 link：

| link | 几何 | 颜色 | 设计位置（相对 skirt） |
|---|---|---|---|
| `skirt` | 圆柱 r0.26 × h0.44 | 深灰 `0.25 0.25 0.28` | 0 |
| `torso` | **胶囊 r0.17 × len0.4** | **蓝 `0.18 0.44 0.82`** | z +0.55 |
| `head` | 球 r0.13 | 肤色 `0.94 0.78 0.63` | z +1.05 |
| `left_wheel` / `right_wheel` | 圆柱 r0.055 | 黑 `0.1` | ±0.20 / -0.225 |

**全场景只有这一个 capsule 几何** —— 用 `grep -i capsule` 扫整个 SDF，只有 `torso` 的 collision 和 visual 两行命中。所以"蓝色胶囊"＝`torso`。

但 `person` 模型只定义了 2 个关节：

```xml
<joint name="left_wheel_joint"  type="revolute"> skirt → left_wheel  </joint>
<joint name="right_wheel_joint" type="revolute"> skirt → right_wheel </joint>
```

**`torso` 和 `head` 没有任何关节连到 `skirt`。** 在 gz-sim 里，没有 joint 的 link 就是**自由刚体**——`<pose relative_to="skirt">` 只影响初始位姿的计算，不会把 link 连起来。

于是开局一瞬间，躯干（蓝色胶囊）和头部（肤色球）直接从人身上掉下来，落到地上被撞飞，之后一直在场里漂。

## 2. 实测证据

运行时抓 `/world/follow_world/pose/info`（link 级世界坐标）：

```
skirt   (  +0.00,   +0.00,  0.280)   ← 人的本体，还站在原地
torso   ( -10.20,   -4.81,  0.790)   ← 蓝色胶囊，已漂到场外
head    (  -8.91,   -7.31,  0.820)   ← 肤色球，已漂到场外
```

场地范围是 ±6m。两个部件早已飞出围栏。间隔 2s 再采一次，`torso` 又滑了 **0.12m** —— 它是带碰撞体的自由刚体，会一直在场里乱滚。

这就完整解释了用户看到的三件事：

| 现象 | 原因 |
|---|---|
| 场里多出一个蓝色胶囊"障碍物" | 掉落的 `torso`（胶囊 r0.17/len0.4，蓝色），带碰撞体，会被撞到、会滚 |
| 人能穿过它 | `person` 的 `self_collide=false`，而且它本来就不在人身上 |
| 机器人识别不到、每次都撞 | 它躺在地上（顶面约 0.34m）。4 台深度相机的有效取带是**仰角 +1.5°~+18°**（下沿刚过车头 0.10m），贴地物体只在带的最下缘露出一条窄边，逐扇区取 5% 分位时会被地面回波稀释掉；而它又是实体，于是就撞上了 |

## 3. 修复

`work_area.sdf` 补两个 fixed joint：

```xml
<joint name="torso_joint" type="fixed">
  <parent>skirt</parent>
  <child>torso</child>
</joint>
<joint name="head_joint" type="fixed">
  <parent>skirt</parent>
  <child>head</child>
</joint>
```

gz-sim 会把 fixed 子 link 合并（lumping）进父 link，质量变成 3+3+1 = 7kg，差速插件的 `max_linear_acceleration 0.9` 仍然够用。

### 修复后验证

```
skirt   (  +0.00,   +0.00,  0.280)
torso   (  +0.00,   +0.00,  0.830)   dxy = 0.000  dz = +0.550  ✓
head    (  +0.00,   +0.00,  1.330)   dxy = 0.000  dz = +1.050  ✓
场外游离刚体检查：无
```

人形完整，总高 1.46m。

## 4. 连带收益（这才是大头）

修之前，场景里的"人"只剩一个 **0.44m 高的深灰圆柱 + 两个轮子**（躯干和头都掉了）。视觉检测的 bbox 只有正常人形的 1/3 高，检出率被这个隐性问题拖累。

修完人形之后（150s 随机行走评测，同一套控制器）：

| 指标 | 修之前 | 修之后 |
|---|---|---|
| 视觉检出率 `vis_pct` | 79.5% | **95.9%** |
| front 相机占比 | 69.2% | **92.9%** |
| 视野切换恢复响应（均值） | 4.83s | **1.06s** |
| 切换响应超时次数 | 27 / 62 | **0 / 5** |
| 丢失事件数 | 6 | **2** |
| GOTO 到点率 | 1 / 11 | **2 / 2** |

## 5. 遗留风险

低矮贴地障碍（躺倒的 capsule 顶面 0.34m、矮墩、地面杂物）落在 4 台深度相机 `+1.5°~+18°` 取带的下沿之外，逐扇区 5% 分位时会被地面回波稀释 —— 这类物体雷达和深度都容易漏。

要彻底解决需要把取带下沿压到 0° 以下并单独处理地面平面（或加一路朝下的近距 ToF），不在本次范围内。

## 附：本轮其它修复（同一个评测里一起验证）

- **P40/P42/P43/P44 距离环重写**：`cmd_gain` 1.62→1.0（被控对象其实 1:1，之前用 `/robot/odom` 标出来的 ×0.62 是假象）；加人速前馈；去掉"带内即停车"；前馈+有界反馈。
- **P44 限速过度保守**：`d_head = min(d_f, min(d_fl,d_fr)*0.72)` 把 45° 方向 0.90m 的障碍折算成 0.65m（< stop_d 0.66），机器人明明能过去却直接停车；限速公式 `(d_head-stop_d)/tau` 在 0.70m 时只给 0.067m/s。这是 in_band 长期卡在 10% 左右的真正原因，改完后 60.1%。
- 最终评测（150s）：**距离带内 60.1%**、中位 1.042m、最近 0.561m、**0 碰撞**（最小间隙 +0.389m）、**最长连续带内 27.3s**。
