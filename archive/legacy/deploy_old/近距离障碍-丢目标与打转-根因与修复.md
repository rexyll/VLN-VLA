# 目标靠近障碍 → 丢目标 → 胡乱移动/打转：根因与修复（P53–P57）

**现象**：被跟随的人走到障碍物附近时，机器人很容易丢失目标，随后原地乱转或瞎走。

**结论**：这条行为链不是感知问题，是**控制层的三条判据在同一时刻互相打架**，最后形成极限环（limit cycle）。三处分别是：

| # | 位置 | 本质 |
|---|---|---|
| 1 | `_safety_gate` 的 `d_head = min(d_f, min(d_fl,d_fr)*0.72)` | 用 8 扇区折现代理判"正前方能不能走"，把**能过的走廊判成过不去** |
| 2 | `v_cap = min(max(approach_speed, v_ff), v_lat)` | 把**抗过冲的安全帽当成了稳态限速**，跟距被钉死 |
| 3 | `path_free` 把"距离"和"走廊宽度"塞进一个返回值 | **重复扣车体半径**，同时放行"贴着角切过去" |

修完这三条，同一条人行走轨迹下（固定随机种子）距离中位数从 **2.98 m → 0.96 m**，全程离障碍 ≥ 0.57 m，丢失时长从 **最长 22.9 s → 0.8 s**。

## 一、现场证据

### 1.1 症状时间线（eval14，150 s）

```
 t=60  rx=-1.77 ry=3.77 d=1.07 cmd_v=+0.10   ← 正常跟随
 t=69  rx=-2.23 ry=3.95 d=1.11 cmd_v=+0.00   ← 开始冻住
 t=81  rx=-2.26 ry=3.99 d=3.67 cmd_v=-0.18
 t=87  rx=-2.20 ry=4.03 d=4.38  lost=60      ← 丢失
 t=123 rx=-2.03 ry=4.06 d=2.66 cmd_v=+0.12   ← 才动, 已过 63 s
```

机器人**冻在 (-2.24, 2.84) 整整 63 秒**，而人从 1.05 m 一路走到 5.0 m。
同一时段的 follower 日志：

```
[对正|视觉] 距离=1.05m 目标方位=+40° ... w=+1.1 对正+40°
[对正|视觉] 距离=1.45m 目标方位=+21° ... w=-0.9 对正+21°(边转边走)
[对正|视觉] 距离=1.60m 目标方位=+15° ... w=-0.9 对正+15°(边转边走)
[对正|视觉] 距离=1.33m 目标方位=+39° ... w=+1.1 对正+39°
[对正|视觉] 距离=1.80m 目标方位=+15° ... w=-1.1 对正+15°(边转边走) 全向急停 前1.63 左前0.34 右前4.45 绕右
[对正|视觉] 距离=1.46m 目标方位=+43° ... w=+1.2 对正+43°
[对正|视觉] 距离=2.08m 目标方位=+10° ... w=-1.1 对正+10°(边转边走) 全向急停 前1.76 左前0.33 右前3.71 绕右
```

`w` 在 **+1.1 / −0.9 之间每 0.5 s 翻一次号**，距离从 1.05 m 单调涨到 2.12 m —— 这就是用户看到的"打转"。

### 1.2 几何：其实过得去

机器人 (-2.24, 2.84, yaw 39°)，人 (-1.13, 4.33)，障碍 ob2 = box(-3.0, 3.2, 1.2×0.6, yaw 0.5)。

```
ob2 的角 (corner) 在车头**左前 64°**、车心到表面 **0.395 m**
沿 39° 航向通过时, 该角的法向间隙 = 0.395 × sin(64°−39°+…) = **0.355 m**
车体外接半径 0.18 m  →  剩 0.175 m 余量, **完全过得去**
```

但旧判据：

```python
d_head = min(d_f, min(d_fl, d_fr) * 0.72)     # 0.34 × 0.72 = 0.245
if d_head <= stop_d(0.66):  v_t = 0;  w_t = 1.15 * esc_dir
```

`0.245 < 0.66` → **急停**，并且急停分支强制往空侧（右）转 `w = −0.9`。
下一个 tick 左前变宽，ALIGN 把车头转回目标（左，`+1.1`）→ 左前再次变窄 → 再急停 ……

**极限环闭合。** `blk_s = 2.2 s` 那条"后退脱困"因为 `d_head > stop_d` 时会把
`_blk_t0` 清零，永远攒不够，一次都没触发。

`0.72` 这个折算本身没错，错在它假定障碍正好在 45°；而 8 扇区每个方向的角跨度
约 20°~70°，**实际角度未知**。在没有真值地图的年代只能这么代理 —— 现在
`GEO` 表里 7 个障碍的位置/尺寸都精确已知（已与 `work_area.sdf` 逐项核对），
没必要再用这么粗的代理。

## 二、三处修复

### 2.1 P53：用真值几何扫掠替代扇区折现

新增，沿车头方向以 5 cm 步长扫到 1.60 m：

```python
def path_free(x, y, ya, margin=0.10, s_max=1.60, step=0.05):
    """返回 (可用直行距离, 走廊是否够宽, 首个拦截物)"""
```

* `d_surf`：沿航向到"车心将触到表面"的距离 —— **就是表面距离**，与扇区距离
  `d_f` 同量纲，可以直接和 `stop_d / slow_d` 比较，**不再重复扣车体半径**。
* `tight`：走廊宽度够不够（沿途任一点中心间隙 < `ROBOT_R + 0.10` 即 False）。

调用点：

```python
_dpath, _okp, _objp = path_free(self.rx, self.ry, self.ryaw)
if not _okp:
    d_head = 0.0            # 走廊太窄(贴角) → 不许再往前挤
else:
    d_head = min(d_f, _dpath)
```

8 扇区的 `fl / fr` 从此**只保留"限速"职责，不再参与"停不停"**。

离线几何对照（`tmp_check_p53.py`，纯计算，不起仿真）：

| 场景 | 旧判 | 旧 d_head | 新判 | 新 d_head |
|---|---|---|---|---|
| **eval14 死锁现场 ob2 角旁** | 停 | 0.245 | **行** | 1.600 |
| ob2 正对（真撞） | 停 | 0.245 | 停 | 0.350 |
| ob1 正前 0.60 m | 停 | 0.600 | 停 | 0.550 |
| **ob1 侧方 0.45 m 平行直行** | 停 | 0.432 | **行** | 1.600 |
| ob7 正前 1.00 m | 限 | 1.000 | 限 | 0.950 |
| ob6 正前 1.10 m（yaw −0.4 斜置） | 限 | 1.100 | 限 | 1.100 |
| 空旷场心 | 行 | 9.000 | 行 | 1.600 |

### 2.2 P54：距离环的帽子语义搞反了

```python
# 旧：把"抗过冲安全帽"当成了稳态限速
v_lat  = (dist - guard_d) / lat        # lat = 0.8 s 视觉时延
v_cap  = min(max(approach_speed, v_ff), v_lat)
```

稳态时 `v_lat == 人速` 恰好平衡 → **跟距被钉在 `guard_d + lat × v_p`**。
`guard_d = 0.65`、`lat = 0.8`、人速 0.2~0.5 m/s → 稳态 0.81~1.05 m。
实测 eval15 中位 **0.908 m**、near(<0.9 m) **48.9 %**、in_band **15.2 %**。

这段代码的**意图**是"视觉时延内不许冲进安全距"，也就是限制**相对接近率**，
不是限制绝对速度。正确写法：

```python
# 新：v − v_p = room/lat → lat 秒内正好走完 room, 不越界
v_lat = v_ff + room / lat
v_cap = max(0.0, min(0.72, v_lat))
```

人站着不动（`v_ff = 0`）时自动退化成旧式，仍在 `lat` 秒内收敛到 `guard_d`。

配套 **P56**：人一转身朝机器人走来时，后退上限 `−0.35` 挡住（人前进 0.4 →
净接近 0.05 m/s，距离被一点点啃到 0.6~0.8 m 再也回不来）。改为 `err_d < −0.12`
时放开到 `−0.55`，后方安全仍由安全层的 `d_b` 判据保证。

### 2.3 P57：`path_free` 的语义拆分（最容易被忽略的一处）

P53 初版把两件事塞进同一个返回值，导致**重复扣车体半径**：正前方 1.0 m 的障碍
被算成 `d_head = 0.65`，再跟 `stop_d = 0.66` 一比，变成**停在 1.0 m 之外**。
拆成 `d_surf` + `tight` 后语义才对。

同时发现一个只有在"贴角"时才暴露的陷阱，必须靠 `tight` 单独拦：

> 扫掠是沿**当前**车头画的直线，但机器人边走边被上层修正 10°~30°，
> 实际轨迹会切到直线的**内侧**。
>
> 实测（`PW_SEED=7`）：机器人贴着 ob5(4.2, −3.0) 的角、以 **0.25 m** 中心间隙
> 切入，最后卡进角里（清距 0.07 m）——
> * 原地转：被物理挡住（车体外接圆扫进障碍）；
> * 后退：ob5 在侧后方，安全层判 `d_b < stop_d` → "后退受阻"；
> * **两条路都堵死 → 冻死 45 s，人从 1.4 m 走到 5.96 m。**

因此补了两条：

* `tight`（margin 0.10 → 30 cm 走廊）：贴着角不许往前挤；
* **贴身回退**：真值清距 < 8 cm 且 `d_b > 0.8 × stop_d` 时 `v = −0.20` 倒出来。

## 五、还没做的

1. **`follower.py` 里 `OBSTACLES`（外接圆表）已无人使用**，但「防撞人」分支仍在
   遍历它做"背后有没有障碍"判断 —— 应统一到 `GEO`。
2. **`min_gap` 在个别轨迹上仍会掉到 0.20 m 左右**（eval16），属"人贴着障碍走、
   机器人贴身跟"的正常代价；如需更大的安全余量，可把 `path_free` 的 `margin`
   从 0.10 提到 0.14（代价是绕障时更容易停）。
3. **真正的绕障仍是缺口**：`use_avoid=false` 时机器人遇到"人站在障碍正后方"
   只能等 `goto_stall`/`scan` 兜底。要彻底解决需要带地图的全局规划（A*/DWA），
   不在本次范围。
