## 4. 同步工具

`vmsync.py` —— 基于 Paramiko SFTP 的双向同步器。

### 4.0 开关机制（默认关闭）

同步工具**默认处于关闭状态**。仓库根目录**不存在** `.vmsync_enabled` 标记文件时，
执行 `scan` / `sync` / `verify` / `pull` / `push` 会被闸门直接拒绝（退出码 2），
且**不会连接 VM、不会读写任何文件**。

```bash
PY="C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe"

# 查询开关状态(不连 VM)
$PY vmsync.py status

# 打开 / 关闭
$PY vmsync.py enable      # 创建 .vmsync_enabled 标记文件
$PY vmsync.py disable     # 删除标记文件, 回到关闭状态

# 单次临时放行(不写标记文件)
VMSYNC_ENABLE=1 $PY vmsync.py scan
```

封装脚本同步支持：`bash vmsync_run.sh [status|enable|disable|scan|sync|verify]`，
不带参数时默认执行 `status`（只读、只显示状态）。

> 设计意图：同步是一次性的人工操作，误触发会造成大范围文件覆盖。
> 默认关闭保证「不主动动、不误动」，需要时显式开启。

### 4.1 用法（需先 enable）

```bash
# 用法
C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe vmsync.py scan     # 只看差异
C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe vmsync.py sync     # 执行同步
C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe vmsync.py verify   # 全量 md5 校验
```

或用封装脚本：`bash vmsync_run.sh [scan|sync|verify]`

### 关键实现要点

1. **排除规则**：`__pycache__`、`.git`、`vla_ws/build|install|log`（colcon 产物）不参与同步。
2. **实时日志**：`p60_run.log`、`traj_fov.log`、`traj_log.csv` 由 VM 端 follower 持续追加，
   字节级必然漂移。策略是**不参与冲突判定**，在同步最后一步统一「VM → 本地」拉一次快照。
3. **上传方式**：该服务器 SFTP `rename` 覆盖会失败（`OSError: Failure`），
   因此统一「先传同目录隐藏临时文件 → `exec_command` 执行 `mv -f` 原子替换」。
4. **Windows 路径转换**：Git Bash 会把 `/home/...` 转成 `C:/Program Files/...`，
   调用 `vm.py` / `vmput.py` 必须加 `MSYS_NO_PATHCONV=1`。
5. **隐藏目录**：远端扫描默认跳过隐藏项，但 `.workbuddy/`（项目工作台，含 memory 日志）必须纳入。

## 6. 约定（后续维护）

- 所有 VM 端的中间产物、脚本副本、实验世界文件一律落在
  `/home/earl/workspace/VLA` 内，不再写到 `/home/earl` 顶层或 `/tmp`。
- **同步工具默认关闭**（无 `.vmsync_enabled` 标记文件）。每次需要同步时先
  `vmsync.py enable`，用完建议 `vmsync.py disable` 复位；
  单次临时操作用 `VMSYNC_ENABLE=1` 放行更轻量。
- 每次在 VM 上完成代码改动后，执行 `vmsync.py sync` 拉回本地；
  本地改动后执行 `sync` 推到 VM。冲突按「mtime 新者胜」自动裁决，
  但**涉及 SDF / 源码等语义文件时建议人工确认**（历史上 P61/P62 的轴向与
  左右轮绑定修正就是靠人工比对 diff 判定的）。
