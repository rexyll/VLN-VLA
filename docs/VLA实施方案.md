## 2. P0 场景定义〔KB-11 P0 / KB-07 图1〕

### 2.1 跑知识库决策树（结论留痕）

```
成功判据可量化? → 是（跟随距离/零碰撞/抓取成功率，均可由仿真真值自动判定）
需要语义泛化?  → 是（语音指令自然措辞、目标物按颜色/名称指定）
有数据采集渠道? → 是（仿真内脚本专家自动采集，零成本）
闭环硬实时 <30ms? → 否（仿真控制 20Hz，允许 50~500ms）
→ VLA 路线成立；但按 KB-03 §1"诚实的技术判断"：
   算力只有 4 核 CPU，7B VLA 不可行 → 采用「分层混合架构 + 教学级 mini-VLA」：
   语音 NLU + 视觉感知 + 经典控制器构成稳定闭环（阶段一/二），
   mini-VLA 作为策略层替换件（阶段三，可选，复用知识库 code/mini_vla 全流程）。
```

### 2.2 任务定义卡

| 项 | 阶段一（移动控制） | 阶段二（抓取放置） |
| --- | --- | --- |
| 任务描述（目标状态导向） | "跟随我，保持 X 米"（X 由语音给出）；"前往/避开某方向" | "抓取红色方块"、"把蓝色圆柱放到托盘上" |

| 泛化需求 | 指令措辞多样（≥3 同义改写/任务）；距离参数任意（1~5m） | 目标按颜色+名称指定；位置随机化 |
| 数据规模（阶段三才用） | 仿真脚本专家 200~400 条/任务 | 同左 |

### 2.3 环境变量（KB-附录A §15 对照）

仿真环境固定光照（world 内已锁定），但深度/RGB 相机受软渲染影响存在帧率波动 → 感知层必须有"帧过期检测"（>0.5s 无新帧 → 降速）。

## 3. 总体架构〔KB-03 §2 / KB-01 §5 双系统〕

### 3.1 分层架构图

```
┌─────────────────────────────────────────────────────────────┐
│ L5 语音层  真人音频 → Vosk ASR → 文本规范化 → 指令模板库匹配    │
│           → 结构化任务指令 {action, distance, target, color}   │
│           （附录A §12：ASR 纠错表 + 低置信请求确认）            │
├─────────────────────────────────────────────────────────────┤
│ L4 感知层  4 向深度相机(10m) → 各向最近障碍距离/自由空间方向      │
│           前向 RGB → 目标物颜色分割 → (阶段二)目标像素+深度→3D   │
│           帧过期检测 → 降级标志                                │
├─────────────────────────────────────────────────────────────┤
│ L3 决策层  System 2（慢，1~5Hz）：任务状态机                    │
│           IDLE→FOLLOWING→GOTO→GRASPING→PLACING→…              │
│           子目标分解：跟随/前往/绕障航点/抓取序列                │
│           （阶段三可选：mini-VLA 策略层替换此处）                │
├─────────────────────────────────────────────────────────────┤
│ L2 控制层  System 1（快，20Hz）：                              │
│           底盘：前馈+P 距离律 / 纯跟踪 / 定点导航               │
│           臂(阶段二)：关节空间 P 控制 / 解析 IK                 │
├─────────────────────────────────────────────────────────────┤
│ L1 安全层  独立节点，永不信任上层输出（§7 详述）                 │
│           限速/软限位/看门狗/急停 —— 一票否决                    │
└─────────────────────────────────────────────────────────────┘
        ↕ gz-transport / ROS 2话题（ros_gz_bridge）↕
   Gazebo Harmonic（物理+传感器渲染+GUI）
```

**双系统映射**〔KB-01 §5〕：System 2 = 语音 NLU + 任务状态机（低频、语义）；System 1 = 20Hz 控制器（高频、反应式）。这与 GR00T/Helix 的双系统思想同构，只是 System 2 用规则而非 VLM 实现——仿真教学场景下的合理选择，阶段三可将 System 2 的"跟随决策"替换为 mini-VLA 模型。

### 3.2 感知→控制数据流（阶段一）


## 4. 阶段一：深度相机 + 语音 → 底盘移动控制（当前阶段）

**目标**：语音指令 + 4 向深度感知驱动的移动控制稳定运行，通过 §6 验收门禁，然后才进入阶段二。

### 4.1 P0 级：深度相机排障（解决 Q1/Q3）

按顺序执行，每步有判据：

1. **话题名核实**：`gz topic -l | grep depth`，确认实际发布的话题（depth_camera 传感器通常发布 `/depth_front/image`、`/depth_front/depth_image`、`/depth_front/points` 三族）。
2. **消息可用性**：Python gz-transport 订阅实测（本方案前已完成同款探针脚本），判据：32FC1 深度帧到达，且值域合理（0.1~12m，中心视场有场景结构对应的深度变化，而非全常数）。
3. **配置修正**：若深度帧全常数/全 inf → 调整 `<depth_camera><output>depths</output></depth_camera>` 配置与 clip 参数后重测。
4. **性能预算**：实测 RTF（`gz topic -e /stats`）；判据 RTF ≥ 0.8。不达标则按序降级：深度 320×240→256×192、5Hz→3Hz、必要时 RGB 相机 10Hz→5Hz。
5. **降级路径 A（深度可用性不达标时）**：RGB 相机（已验证可用）+ 已知障碍物地图做"深度估计代理"；降级路径 B：真值位姿 + 静态地图几何计算各向距离（"完美传感器"假设，标注为演示用）。**任一降级都在文档与日志中显式声明，不冒充深度相机。**

### 4.2 感知层 depth_percept 节点（新增）

- 订阅 4 路 `/depth_*/depth_image`；
- 每路：中心 60% 视场 → 过滤 inf/NaN/<0.1 → 取 5% 分位（抗噪）得该向最近距离；
- 发布 `/perception/proximity`（`{front, left, right, back, stamp}`，5Hz）+ 帧龄；
- 与真值几何（墙 + 7 障碍物 + 人）自动对比，输出**感知误差指标**（阶段一验收项之一）——这是"深度相机视觉感知确实在工作"的量化证据。

### 4.3 语音指令集与 NLU 扩展（voice_node 升级）

〔KB-附录A §12：ASR→文本规范化→模板库→低置信确认〕

| 类别 | 指令（含 ≥3 同义改写） | 解析结果 |
| --- | --- | --- |
| 跟随 | "请跟随我，保持X米的距离"/"跟我走，隔X米"/"跟上我" | `{action:FOLLOW, distance:X}`（X 缺省 2.0，中文数字解析已实现） |
| 停止 | "请停止跟随"/"停下"/"站住" | `{action:STOP}` |
| 定向移动 | "向前走X米"/"左转90度"/"后退一点" | `{action:MOVE, dx,dy,dθ}` |
| 前往 | "去工作区中心"/"回到出发点" | `{action:GOTO, target}` |
| 巡逻 | "巡逻一圈"/"绕障走" | `{action:PATROL}` |
| 感知查询 | "前方有什么"/"报告距离" | `{action:QUERY}` → 语音播报（TTS）+ 日志 |
| 阶段二抓取 | "抓取红色方块"/"把它放到托盘上" | `{action:GRASP, color, shape}` / `{action:PLACE, target}` |

规范化层：标点/全半角/数字归一（已有）+ **ASR 纠错表**（"跟随/然后/队形"→跟随 等 Vosk 高频错词）+ 未匹配指令回复"没听清，请说'跟随我'或'停止'"（低置信确认，不盲执行）。

### 4.4 跟随/导航控制（follower v3 收尾验证）

已实现待验证的方案（含缺陷修复过程，全部有数据依据）：

| 历史缺陷（实测） | 根因 | v3 修复 |
| --- | --- | --- |
| 机器人贴人 0.03m 卡死 | 钻入"人"裙摆碰撞体悬空区 | 裙摆碰撞体落地 + 距人<1.2m 后退（后退前查身后障碍） |
| 永远吊在 2.5m 外追不上 | 纯 P 控制稳态误差（v=K·e，e≠0 才有速度） | **前馈+P：v = 人速 + K·(dist−D)**，人停→前馈 0→机停 |
| 绕障卡死 16s | 势场对冲局部极小 | 切点航点绕障（"机器人→人"连线穿膨胀圆时取侧方切点，锁边绕行，8s 超时换边） |
| 原地转身耗时大 | >90° 即完全停车转身 | 仅 >125° 停车转身（2.0 rad/s），其余边走边转（cos 衰减） |

**验证协议**（§6 门禁的量化来源）：连续 ≥3 轮、每轮 ≥90s、语音触发；统计距离命中率（1.5~2.5m 占比）、最小障碍/墙间距（真值轨迹）、"人停→机停"响应时延、语音端到端响应时延。

### 4.5 阶段一验收门禁（Gate-1）

| 指标 | 标准 | 判定来源 |
| --- | --- | --- |
| 语音识别准确率（指令级） | ≥ 90%（每类指令 ≥10 次） | voice_node 日志 |
| 语音端到端响应 | ≤ 2s（音频结束→底盘开始动作） | 日志时间戳 |
| 跟随距离命中（1.5~2.5m） | ≥ 70%（稳态段，剔除指令后 5s 瞬态） | follower 日志统计 |
| 人停→机停 | ≤ 2s，且停车时与人距离 ≥ 1.2m | 真值轨迹 |
| 零碰撞（障碍/墙/人） | 100%（安全层零漏放） | 真值几何离线判定 |
| 感知有效性 | 深度各向误差 ≤ 0.3m（vs 真值几何）；或显式声明降级 | depth_percept 对比指标 |
| 仿真稳定性 | 连续运行 ≥10min 无崩溃，RTF ≥ 0.8 | gz stats + 进程监控 |

**用户指定的关卡**：Gate-1 全绿并现场演示确认后，才启动阶段二开发。

## 5. 阶段二：机械臂 + 夹爪 → 视觉 + 语音抓取/放置

〔KB-附录A §2 移动操作：底盘与臂解耦、基座位姿并入感知〕

### 5.1 硬件（SDF 建模）

- 3 自由度平面关节臂（基座旋转 + 大臂 + 小臂）+ 1 自由度平行夹爪，安装于底盘上方转台；关节位置控制用 gz `JointPositionController` 系统插件，20Hz。
- 设计工作半径 0.8m、举升高度 0.6m，覆盖地面至 0.5m 抓取层。
- 夹爪语义写进元数据（0=张开，1=闭合）——KB-09 §2 "gripper 语义反转"是现场事故高发区。
- 场景新增：3~5 个彩色物体（红方块/蓝圆柱/绿方块…）+ 放置托盘；物体属性（质量/摩擦）调至夹爪可可靠夹持。

### 5.2 感知扩展

- RGB 前向相机：HSV 颜色分割 → 目标物体像素域（质心+面积）；阶段二可选升级：顶视全局相机辅助定位。
- 深度（前向）：目标像素域深度中位数 → 相机系 3D →（外参标定，复用 KB calibrate.py 思路）→ 世界系坐标。
- 里程计漂移问题已知（轮式 odom yaw 漂移）→ 抓取对准用**相机系闭环视觉伺服**（像素误差直接驱动底盘/臂），不依赖世界系绝对定位精度——规避 KB-09 §2 坐标系坑。

### 5.3 任务状态机（System 2）与抓取序列

```
GRASP(color, shape):
  SEARCH   → 转台+底盘缓慢扫描, RGB 分割锁定目标 → 失败(10s) → 语音播报"没找到"
  APPROACH → 底盘视觉伺服对准(目标质心→图像中心, 深度→0.45m 预抓距)
  ALIGN    → 臂末端伺服到物体上方; 深度确认高度
  GRASP    → 夹爪闭合 → 力/接触判定(夹爪关节负载或物体位姿变化) → 失败重试≤2次
  LIFT     → 抬升 0.3m, 确认物体离地(真值辅助判定)
PLACE(target):
  CARRY    → 底盘导航到目标区(复用阶段一避障控制)
  LOWER&RELEASE → 下降到位, 张爪, 确认物体在目标区
```

每步有超时与失败出口 → 语音反馈（TTS）→ 安全停止。这正是 KB-附录A §8"长时程任务显式状态机 + 失败恢复"的最小实现。

### 5.4 阶段二验收门禁（Gate-2）

| 指标 | 标准 |
| --- | --- |
| 抓取成功率（物体位姿随机化） | ≥ 70%（每物体 ≥20 次，报 Wilson 95% CI，复用 KB evaluate.wilson_ci） |
| 放置成功率 | ≥ 60%（同上） |
| 语音抓取指令准确率 | ≥ 90% |
| 移动+抓放全流程 | "抓取红色方块放到托盘" 一句话完成，≤ 90s |
| 安全 | 全程零碰撞；臂越界零次（软限位拦截计入但不得漏放） |
| 失败处理 | 每类失败（找不到/抓空/掉落）有明确语音反馈与恢复路径 |

## 6. （可选）阶段三：mini-VLA 策略层 —— 完整 VLA 训练闭环

> 目的：把阶段一的"跟随/前往"决策从规则替换为**训练得到的小型 VLA 模型**，完整走通知识库 04/05/08/10 的 数据→训练→评估→部署 流程。CPU 可跑（复用 `code/mini_vla`，实测教学级训练分钟~小时级）。

- **数据**〔KB-04〕：仿真脚本专家（当前 person_walk/follower 的专家逻辑）自动采集 200~400 条/任务；观测 = 顶视/深度下采样图像 + 本体感知（底盘位姿+速度）；动作 = (v, ω) 增量块 H=16；**LeRobot v2 格式 + q01/q99 归一化统计随 ckpt 归档（四件套）**；指令 = 每任务 ≥3 同义改写（含中文）；按 episode 划分 train/val 防泄漏。
- **训练**〔KB-05〕：改造 `train.py`——输入图像换成本项目相机流，动作维 2（底盘）；掩码 L1 + 动作块；固定 seed；实验卡记录。
- **评估**〔KB-10〕：`evaluate.py` rollout + Wilson CI；评估矩阵（位姿随机 × 指令改写 × 干扰物），与规则版 follower 同场对比。
- **部署**〔KB-06〕：`server.py` FastAPI 异步推理 + 控制回路消费动作块（receding horizon）+ 看门狗——落地 KB 的推理/控制解耦架构。
- **易错点内置**〔KB-09 §12 实录〕：观测-动作因果对齐（state[t]=执行前观测）、记录动作=执行动作、成功后零动作长尾截断、线性头（非 tanh 饱和）——知识库已修过的坑在数据生成器中直接规避。

## 7. 部署架构与安全层〔KB-06 / KB-10 §5〕

### 7.1 进程拓扑（VM 内）

```
gz sim (server+GUI, ogre1 GUI / ogre2 sensors)
 ├─ ros_gz_bridge (config_file 模式, 话题映射)
 ├─ voice_node      L5  ASR+NLU（Vosk 模型常驻）
 ├─ depth_percept   L4  深度聚合（阶段一新增）
 ├─ brain_node      L3  任务状态机（阶段二新增；阶段三可挂 mini-VLA 推理服务）
 ├─ follower        L2  底盘控制 20Hz
 ├─ arm_controller  L2  臂控制 20Hz（阶段二新增）
 └─ safety_node     L1  安全层（独立节点, 订阅所有 cmd_vel, 一票否决后转发 gz）
launch: ros2 launch vla_follow demo.launch.py [auto_voice:=…] [voice_delay:=…]
```

### 7.2 安全层规则（独立于任何模型输出，逐条校验）

1. **看门狗**：上层指令断流 >0.5s → 置零速度；>2s → 任务状态机复位；
2. **软限位**：底盘 |x|,|y| ≤ 5.75m；臂关节限位盒；越界裁剪并记日志；
3. **限速**：底盘 |v| ≤ 0.8m/s、|ω| ≤ 2.2rad/s；近人（<1.5m）≤ 0.2m/s；臂关节速度上限；
4. **近距硬停**：真值几何 + 深度感知双通道，任一发现 <0.35m 且靠近 → 停车；
5. **输入校验**：深度/RGB 帧龄 >0.5s → 降速 50%；NaN/inf → 停车；
6. **急停**：语音"停/站住/停止"直接由安全层优先处理（不经状态机排队）；键盘/话题急停接口保留。
安全用例进入阶段一/二评估矩阵（KB-10 §2 末行），改版必重跑。

### 7.3 监控与数据飞轮（最小版）

- 每次运行自动落盘：/rosout 日志 + follower/感知指标 + （阶段二）任务成败标签；
- 周期统计：语音识别错误表、安全层拦截 Top 原因、RTF/帧龄分布；
- 失败片段回流为阶段三训练数据（如启用）。
