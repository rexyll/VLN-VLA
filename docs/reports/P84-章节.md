## 25. 双臂递水任务：从场景建模到端到端闭环（P84–P92）

> 本章是"机器人给人倒水递水"这一整段的存档。任务分解与每日状态见
> `TaskPlan.md` §3；逐条踩坑的现象/根因/修法见 `TaskPlan.md` §6.4 #19~#54。
> 本章只讲**定案与理由**，不复述调试过程。

### 25.1 需求与验收口径

在已跑通的"语音驱动跟随"之上叠加双臂操作：机器人装 2 条 7 轴机械臂 + 2 只
Shadow Hand 灵巧手，场景里有一张桌子、一把水壶、一个带柄水杯。完整闭环是：

```
人走到桌边说"我要喝水"
  → 机器人抓壶、倒水入杯（水位可见上升）
  → 壶放回原位 → 双手捧杯转身面向人（杯柄朝人，方便接）
  → 前伸递到人手边 → 人接杯喝 → 双手接回
  → 转回桌前、杯子放回原位
  → 双臂收回、撤离桌边 → 把底盘交还给跟随 → 人走开，机器人跟上去
```

验收口径（每条都有自动化脚本，不靠肉眼看）：

| 环节 | 指标 | 脚本 |
|---|---|---|
| 场景/模型 | 37 路话题、34 路关节反馈、51 实体、壶/杯 0.0 mm、双 7 轴 0.0° | `test_scene.py` 6/6 |
| 关节通道 | 37/37 话题 @20 Hz、双臂 0.00°、FK-真值 0.0 mm | `test_pose.py` 6/6 |
| 抓壶 | IK 0.1 mm / 余量 52~56°、抓取位 2.8~4.1 mm | `test_p86.py` 9/9 |
| 倒水 | 水位 65 %、水柱 159.9 mm、壶倾 68° | `test_p87.py` 10/10 |
| 捧杯转身 | 双手横向间距 0.107~0.138 m、转身前后杯子 base 系 0.0 mm | `test_p88.py` 10/10 |
| 递接放回 | 递到人手 12.9~24.8 mm、交接漂移 0.0 mm、放回 0.2~3.0 mm | `test_p89.py` 10/10 |
| 端到端 | 一条命令跑完 9 阶段、杯回原位 ≤1.5 mm、恢复跟随末段 0.82~1.12 m | `test_drink.py` 8/8 |

### 25.2 场景：坐标只有一个真源

所有几何常量集中在 `vla_follow/scene_layout.py`，SDF（`tools/gen_drink_scene.py`）、
桥接配置、运行时三处都从这里取值。改布局只改这一个文件，然后：

```
python3 tools/gen_drink_scene.py   # 重新生成 SDF
python3 tools/check_ik.py          # 离线可达性体检（11 项）
python3 tests/test_drink.py        # 端到端复验
```

关键自洽关系（改数前务必保持）：

```
|PERSON_SPOT − SERVE_POSE| = CUP_PRESENT_R + PERSON_HAND_FWD = 0.62 + 0.30 = 0.92
```

即"机器人把杯子前伸 0.62 m"正好落在"人前伸 0.30 m 的手上"。这条关系一破，
整条链会在递杯那一步失败，而且现象是"杯子够不着"这种看起来像 IK 问题的假象。

P92 又补了两个撤离位，同样带自洽约束：

| 常量 | 值 | 约束 |
|---|---|---|
| `SERVE_RETREAT_XY` | (0.60, 0.35) | 距桌心 2.0 m > follower 膨胀圈（0.62+0.56=1.18 m），交权时机器人已在圈外 |
| `PERSON_LEAVE_SPOT` | (1.35, 2.72) | 距桌心 2.6 m、距机器撤离位 2.5 m —— 太近人走两步出画，太远 follower 要搜很久 |

### 25.3 抓取附着：定案是世界内 C++ 插件

**不物理抓取。** 上位机按实测掌心位姿算出"物体该在哪"，每 tick 由世界内插件
把物体钉在那个位姿上。三条路的对比：

| 方案 | 结论 |
|---|---|
| `DetachableJoint` 插件 | ❌ 它本身会破坏机械臂关节的约束求解（#19）—— 这是 P85 的头号大坑 |
| 外部进程高频调 `/world/<w>/set_pose` | ❌ 服务调用开销 + 时序不可控（#20） |
| **世界内 `gz::sim::System` 插件**（`GraspCarry.cc`） | ✅ 定案 |

`GraspCarry` 是**纯执行器**，运动学只有 `arm_kin.py` 一份真源。接口：

```
grab    <model> x y z qx qy qz qw   登记目标（回 ack）
set     <model> x y z qx qy qz qw   更新目标（不回 ack，高频）
place   <model> x y z qx qy qz qw   一次性摆位（布景用）
joint   <model> <joint> <value>     运动学驱动某个关节（回 ack）
release <model> / release all       取消跟随（回 ack）
```

两个必须记住的实现细节：

- **`joint` 指令是为壶/杯上的滑动副（jet / water）准备的。** 它们是**速度模式**
  的 `JointPositionController`，而所属模型被插件每 1 ms teleport 一次，速度指令
  会被 teleport 的清零抢走 —— 同一条命令时而完全不动、时而只走一部分（jet
  0.124/0.16、water 0/0.012），全是操作顺序的竞态（#29）。改成每 tick 写
  `JointPositionReset`（与 teleport 同源的运动学驱动）才稳。
- **`grab` 只对第一针回 ack**（#34）。首针丢了就永远等不到，所以整段都发
  `grab`（幂等），不要"第一针 grab、之后 set"。

### 25.4 运动原语库（`drink_motion.py`）

九个原语覆盖整条链，后面所有阶段都是它们的组合：

| 原语 | 作用 | 要点 |
|---|---|---|
| `reach` | 精密到达目标掌心位姿 | 闭环补正，返回 (是否, 残差, 方式) |
| `place_held` | 把手里的物体送到世界位姿 | **位置 + 姿态双闭**（只闭位置会卡在毫米之上 #30）；连续两轮达标才返回（#37，手臂还在滑行）；达标分支**不能再补一步 reach**（会把物体自己推开 #38） |
| `put_down` | 松手放回 | 顺序固定 **张手 → 对位 → 松钉 → 撤手**（#28） |
| `turn_base` | 原地转身 | 走 `/robot/cmd_vel` **真转**（teleport 一帧闪现看不出动作）；半速 + 真值 yaw 闭环 |
| `place_robot` | 摆正底盘 | teleport，多放两针收敛（`place` 有 0~18 mm 残留抖动 #32） |
| `hand_onto` / `follow_hand` | 第二只手贴上去并冻结偏移 | 冻结偏移而不是每拍重解 IK |
| `hand_gap` | 掌心在**物体系**下的位置 | 判"双手是否叠在一起"要用物体系分量，不能用世界距离（#38） |
| `pour_into_cup` / `prepare_present` | P87 / P88 整段打包 | — |
| `drive_to` | 真值闭环开到世界坐标 | P92 新增，撤离桌边专用；目标在车体正后方时先原地掉头再前进 |

### 25.5 三个反复出现的判断原则

这段工作里真正值钱的不是某个数字，而是三条判据方法：

**(1) 守恒量判"没掉/没滑"，不要用世界期望位。**
世界期望位会被底盘漂移污染。P88 判"转身有没有把杯子甩掉"时，用世界期望位量出
38.5 mm 的假 NG，改用 `inv(base_pose) @ T_cup` 的 **base 系守恒量**后是 0.0 mm
（#36）。

**(2) 判据要双向卡。**
P89 里"人举杯抬高多少"只写了下界（`dz > 100`），结果人**没站到接水位**、
`hand_to` 冻结的 1.2 m 力臂被绕肩旋转放大，杯子被抡飞 79 cm —— 843 mm 反而
判成了成功。加上上界（`100 < dz < 300`）才暴露出来（#42）。

**(3) 布景自己负责。**
验收脚本必须显式把对象摆到位并核对，不能指望"场景初始位置刚好合适"。上面那个
1.2 m 力臂的坑就是这么来的。

### 25.6 人的指令链路（P90）

```
send_person_cmd.sh drink
  → /person/command {"action":"GO_DRINK"}
person_walk：GOTO（真值闭环 + 切向绕障 + 转向阻尼）
  → 站定、面向机器人
  → /voice/request "text:我要喝水"
voice_node：解析（支持 text: 直通，也支持真 wav 走 ASR）
  → /robot/command {"action":"DRINK","source":"text"}
follower 停车让权 + cmd_mux 上 300 s 锁 → drink_task 排队执行
drink_task 收尾 → RETREAT → /robot/command {"action":"FOLLOW"} → 交还
```

三个设计点：

- **脚本只发 `GO_DRINK`，那句"我要喝水"必须由"人"走到位之后自己说。** 为了图省事
  直接在脚本里发 `DRINK`，等于绕过 `person_walk` 和 `voice_node`，什么都没验（#48）。
- **`follower.OBSTACLES` 里不能加桌子。** 那张表要额外 `INFLATE=0.56`，桌子外接圆
  0.62 → 膨胀到 1.18 m，而服务位距桌心只有 0.85 m，机器人会被判"站在障碍里"、
  永远靠不近桌边。桌子只进 `GEO`（真实 OBB 距离）；`person_walk.OBSTACLES` 与
  `gen_map.OBSTACLES` 则必须加（#47）。
- **人的 GOTO 有自己一套运动层**（`_truth_pose` / `_drive_to_xy`，P92 抽成公共件）：
  真值闭环（里程计走 1.2 m 漂 20 cm #50）、挡路判据用**线段垂距**而不是方位角
  （只按方位角判会在距目标 0.33 m 时把侧向桌子误判成挡路，来回震荡 400 s #49）、
  **v=0 的纯转向是极限环**（yaw 以 3 s 周期摆 ±0.2 rad，小误差区间要给一点前进
  速度当阻尼 #51）。

### 25.7 端到端与回环（P91 / P92）

`tests/test_drink.py` 用 `DrinkTask(observer_only=True)` **只读观察**（不挂 20 Hz /
50 Hz 定时器），否则会和常驻节点抢同一个发布者。判据 8 项：

```
[1] 数据链路   [2] 一条 GO_DRINK   [3] 语音→指令   [4] 人走到接水位
[5] 9 阶段全流程   [6] 杯子放回原位   [7] 交权后恢复跟随   [8] 阶段截图
```

三点值得记：

- **状态一变就广播一次**（`_set_state`），不能只靠 5 s 心跳 —— 端到端脚本要靠
  `/drink/state` 抓阶段截图，心跳跟不上。
- **完成态必须回 IDLE**。停在 DONE 会让下一轮测试一启动就误判"已完成"（#52）。
- **[7] 交权后恢复跟随**用**行为**判，不看 follower 内部状态：机器人总路程 >1 m
  （真的开了）+ 观察末段人机距离 <2.5 m + 跟随带内占比。实测交权后 75 s 内机器人
  走了 13.8~18.6 m、末段距离 0.82~1.12 m、跟随带（1.0±0.35 m）内 89~96 %。
- **"交权"不是发一条消息就完事。** 轻量演示脚本原本不起 follower / 感知 / cmd_mux
  （P90 时为免干扰），`FOLLOW` 发了没人接：没有 cmd_mux，follower 的
  `/cmd_vel_follow` 到不了 `/robot/cmd_vel`；没有感知，follower 不知道人在哪（#53）。

### 25.8 遗留与改进方向

| 项 | 现状 | 说明 |
|---|---|---|
| 前伸 0.62 m 时的伺服不动点 | 5~15 mm | 手臂接近伸直时 7 轴串联的极限，加迭代无用；判据已卡任务指标（递到人手 <45 mm）而不是内部残差（#45） |
| 姿态精度上限 | ~1.6° | 每轴 0.25° 判据在 7 轴串联后的放大；`tol_deg` 定 2.0、验收阈值 2.5°（#39） |
| 倒水仍是"滑动副 + 水柱"，非流体 | 水位/水柱按行程插值 | 视觉上足够，若要真实液面需换流体/粒子方案 |
| 人只有一条手臂自由度 | `person_arm_joint` 单轴绕肩 | 接杯/举杯够用；若要"双手接杯"需扩模型 |
| Nav2 在喝水演示里未启用 | follower 降级成"就地扫描" | 远距离追人靠扫描；若要跨场地导航需补 Nav2 |
| gz GUI 截图服务 | `/gui/screenshot` 返回 true 但找不到文件 | 不影响，看画面走 `/drink_cam` |
