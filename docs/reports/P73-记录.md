## P73 距离环人速前馈（23:00–23:55）— 修了 3 个真 bug，但指标没改善

**目标**：§12.6 的稳态差（`v=k(d−1.0)` 必然停在 `1.0+v_person/k`）用前馈消掉。

**三个真 bug（本轮唯一确定收益）**
1. **`_gap6` 从未赋值** → 「真值硬保」分支必现 `NameError`。改 `geo_gap(rx, ry, _obj6)`。
2. **`path_free` 静默停车**：`_ok6` 是 1.6m 扫掠布尔量，**旁边有柱子就 False**，且 `_obj6 is None` 时既不写 note 也不给转向 → `dh` 恒 0、指令 v 恒 0。日志实证：`距离=2.44m ff=-0.25 pid=+0.20 cap=+0.72 dh=0.00 df=1.48`，人在正前方却原地不动。改 `if _dpath < 0.33: v_t = 0.0`（只认真实接触）。
3. **前馈方向反了**：用 2D 位置窗最小二乘，受 **1° 方位量化噪声**污染（1.5m 处 ±0.26 m/s、2.5m 处 ±0.4）→ 人正接近（0.83→0.55m）却 `ff=+0.50` 全速推，把人顶到 **0.41m** 占满画幅 → 整帧漏检 → 丢失。改为标量观测 `robot_vfwd + d(dist)/dt`（0.7s 窗、0.5s 断窗、clamp −0.60~0.85）。

**`d_head` 一刀切**：`_safety_gate` 的 `elif not _okp: d_head = 0.0` 同病，改 `d_head = min(d_f, _dpath)` + 窄道限速 0.40。

**三次走错又回退（务必记住，都是"加约束把系统锁死"）**
- `_s6 < 0.30` 与 `_dpath` 同时判死：`_s6` 在「已在窄带内」时**从 0.05 起算** → 一进窄道就自我锁死。t8 窄道硬停 50 次，人从 1.0m 走到 5.7m 机器人不动。
- `d_head = min(d_head, _stight + stop_d)`：软死锁，t9 `far` 63.7%。
- 接近率闸 `v_cap = min(v_cap, max(0, v_ff + (dist−0.90)/0.45))`：t11 `near` 41.3%、居中 72.6%、丢失均时 27.55s。

基线全项最好，且差距（98.2% vs 55.2%）不是噪声能解释的。

**为什么不能归因 —— 这是方法学问题**
`person_walk` 主循环用 `time.time()` 而非 `/clock`，`random.seed(PW_SEED)` 之外还有大量时序依赖。实测**同一个 `PW_SEED=7` 连跑两次，人的位置偏差 11m**。每轮走的是不同的路，`in_band` 的 20~39% 波动里分不清代码影响与场景差异。另有一次基准污染：`voice_node` 播 `follow_2m.wav` 把 `target_d` 改成 2.0（日志 `目标2.00m` 出现 111 次），已用 `tmp_run_eval.sh` 全程发 `FOLLOW distance=1.0` 修正。

**下一步不要调参**，先做评测可重复性：①时间源改 `/clock`；②人/机器人/障碍初始位姿固定常量；③所有 `random` 收敛到单个 `random.Random(seed)`；④加回放校验（同 seed 连跑两次 `max|Δ| < 0.05m`）。

**环境坑（新增）**
- `Z:\VLA` 是 SMB 挂载（`\\192.168.255.128\workbuddy_share`）。`TaskPlan.md` 和 `.workbuddy/memory/*.md` 的 ACL 只给 Linux 侧 uid 1000（SID `S-1-22-2-1000`）写权限，Windows 侧 `Administrator` 只有读 → **Edit/Write/追加一律 `Permission denied`**，Edit 工具报的是 `ModifyBackup failed ... UNC\...  not found`。做法：内容写到本地临时文件 → paramiko `sftp.put` 到 `/tmp` → 在 VM 侧用 python 读改写。
- 装 paramiko 的是 `C:\Users\Administrator\.workbuddy\binaries\python\envs\default\Scripts\python.exe`，不是 3.13.12 基础解释器。
