# VLA 部署文档

本文档覆盖：环境依赖、目录约定、安装、编译、启动、参数配置、测试、
打包分发与故障排查。所有路径以 `$VLA_HOME` 表示项目根（默认
`/home/earl/workspace/VLA`）。

---

## 1. 环境要求

| 项 | 版本 | 说明 |
|---|---|---|
| 操作系统 | Ubuntu 24.04 | 其他版本未验证 |
| ROS 2 | Jazzy Jalisco | `/opt/ros/jazzy` |
| Gazebo | Harmonic（gz-sim 8） | 由 `ros-jazzy-ros-gz` 带出 |
| Python | 3.12 | 系统自带 |
| 图形 | X11 / DISPLAY=:0 | Gazebo GUI 必需；无显示器需 Xvfb |

### 1.1 ROS 包

```bash
sudo apt install -y \
  ros-jazzy-desktop \
  ros-jazzy-ros-gz-sim \
  ros-jazzy-ros-gz-bridge \
  ros-jazzy-nav2-bringup \
  ros-jazzy-tf2-ros \
  ros-jazzy-tf2-ros-py
```

`nav2_follow.launch.py` 直接拉起的子包（随 `nav2-bringup` 安装）：
`nav2_map_server`、`nav2_planner`、`nav2_controller`、`nav2_behaviors`、
`nav2_bt_navigator`、`nav2_velocity_smoother`、`nav2_lifecycle_manager`。

### 1.2 Python 依赖

```bash
sudo apt install -y python3-numpy python3-opencv
pip3 install --break-system-packages vosk    # 离线中文语音识别
```

Vosk 中文模型（约 50 MB）放到 `vla_demo/vosk-model-small-cn-0.22/`：
<https://alphacephei.com/vosk/models>

### 1.3 硬件

4 vCPU / 8 GB 即可。10 Hz 四路 RGB-D（320×240）实测 RTF≈1.0、CPU 空闲约
40 %，瓶颈在 VMware SVGA 软件渲染而非算力。

## 4. 启动

### 4.1 一键启动（推荐）

```bash
bash $VLA_HOME/tests/boot_demo.sh 7
```

内部流程：清场（pkill gz / nav2 / launch）→ `vla_demo/start_demo.sh` →
等待 `/person_vision` 节点出现 → 打印节点数。seed 参数控制人的随机行走
序列，固定 seed 可复现。

`start_demo.sh` 的关键机制（改动前请先读）：

- **实例互斥锁** `/tmp/vla_start_demo.lock`，陈旧锁自动清除；
- **Gazebo 单实例**：gz 由脚本启动，ROS launch 传 `start_gz:=false`；
- 启动前调 `gen_map.py` 生成 Nav2 地图、`gz_gui_fix.py` 重写 GUI 布局。

### 4.2 直接启动

```bash
cd $VLA_HOME && env DISPLAY=:0 PW_SEED=7 bash vla_demo/start_demo.sh
```

环境变量：

| 变量 | 作用 |
|---|---|
| `VLA_HOME` | 项目根，默认 `/home/earl/workspace/VLA` |
| `PW_SEED` | 人的随机行走种子 |
| `PW_REPLAY` | 回放轨迹文件（如 `tests/data/walk_rec.jsonl`），指定后按录制轨迹走 |
| `DISPLAY` | X11 显示号 |

### 4.3 下发指令

```bash
bash $VLA_HOME/tests/follow_cmd.sh                 # 命令行下发 FOLLOW 1.0m
bash $VLA_HOME/vla_demo/send_voice.sh <wav路径>    # 走语音识别链路
```

语音指令示例：「请跟随我」「保持两米的距离」「停止跟随」。

### 4.4 观察与停止

```bash
grep FOLLOWER $VLA_HOME/vla_ws/logs/demo.log | tail -5
bash $VLA_HOME/vla_demo/show_follow.sh
bash $VLA_HOME/vla_demo/stop_demo.sh
```

### 4.5 喝水演示（双臂 + 灵巧手递水）

喝水任务**不跟跟随演示共用同一套启动脚本**，原因是它需要一组额外节点：

| 脚本 | 起的节点 | 说明 |
|---|---|---|
| `tools/start_scene.sh [--gui]` | gz 世界 + `parameter_bridge` | 世界由 `tools/gen_drink_scene.py` 生成；`--gui` 同时开 Gazebo 窗口 |
| `tools/start_drink_demo.sh` | `depth_percept` / `person_vision` / `cmd_mux` / `follower` / `person_walk` / `voice_node` / `drink_task` | **P97 起默认带 Nav2**：`gt_tf`（真值定位桥）+ `nav2_follow.launch.py`（6 节点最小栈）+ `gz_viz`（GUI 里品红=规划路径）。`NAV2=0` 退回旧行为。底盘安全由 cmd_mux 的 `/nav2_active` 择路 + 喝水 300s 输入锁保证；follower 启动时后台预热 Nav2 action client（首次丢失不再撞发现期）。P98 起 drink_task 自带**道具自愈**：壶/杯丢失（漂出场外等）5s 内按名义位姿自动重建 |
| `vla_demo/send_person_cmd.sh drink` | — | 只给"人"发 `GO_DRINK`；那句"我要喝水"是**人走到桌边之后自己说的** |

```bash
bash $VLA_HOME/tools/start_scene.sh --gui
bash $VLA_HOME/tools/start_drink_demo.sh
bash $VLA_HOME/vla_demo/send_person_cmd.sh drink     # drink / walk / stop（可选）
```

**最后一步是可选的**：机器人平时一直在跟随人，"人"自己会随机想喝水
（首次 45 s 后，之后每隔 90~180 s），想喝了自己走到桌边开口，机器人让位做
倒水 / 递水 / 接回 / 放回，做完撤离桌边、把底盘交还 follower，继续跟着人
走。`send_person_cmd.sh drink` 只是"替他决定现在去喝一次"。

`person_walk` 的相关环境变量：

| 变量 | 默认 | 说明 |
|---|---|---|
| `PW_AUTO_DRINK` | `1` | `0` = 关掉随机喝水，只留手动下发 |
| `PW_DRINK_FIRST` | `45` | 启动后第一次"想喝水"的延迟（秒） |
| `PW_DRINK_GAP_MIN` / `MAX` | `90` / `180` | 两次喝水之间的随机间隔（秒，**从喝完起算**） |
| `PW_DRINK_JITTER` / `_DEG` | `0.06` / `8` | 人每次站的位置偏差（米 / 度） |

```bash
# 跑 P94 扰动验收时必须关掉随机喝水，否则自发行为会和验收下发的指令打架
PW_AUTO_DRINK=0 bash $VLA_HOME/tools/start_drink_demo.sh
```

观察：

```bash
tail -f $VLA_HOME/vla_ws/logs/drink.log              # 喝水任务各阶段
tail -f $VLA_HOME/vla_ws/logs/pw.log                 # "人"的走位与说话
ros2 topic echo /drink/state                         # 阶段状态（一变就广播）
```

**改布局的正确姿势**：所有桌子/水壶/水杯/服务位/接水位坐标都在
`vla_ws/src/vla_follow/vla_follow/scene_layout.py`（唯一真源）。改完之后：

```bash
python3 tools/gen_drink_scene.py                     # 重新生成 SDF
python3 tools/check_ik.py                            # 离线可达性体检（11 项）
python3 tests/test_drink.py                          # 端到端复验
```

不要手改 `work_area.sdf` 里由脚本生成的那一段，下次生成会被覆盖。

## 5. 参数配置

全部可调参数在 **`vla_demo/vision_config.json`**，follower 与 person_vision
共用同一份，改完重启 demo 生效（无需重新编译）。

### 5.1 跟随距离

| 参数 | 默认 | 说明 |
|---|---|---|
| `track_dist_m` | 1.0 | 目标跟随距离 |
| `track_dist_tol_m` | 0.5 | 合格带宽（0.5~1.5 m 视为达标） |
| `vis_bias_m` | 0.357 | 相机测到人体表面的偏置，换算到「人中心到车中心」 |

### 5.2 对正与转向

| 参数 | 默认 | 说明 |
|---|---|---|
| `aim_band_deg` | 15 | 超出该偏离角进入 ALIGN 原地对正 |
| `recenter_kp` / `recenter_rot_speed` | — | 对正比例增益与角速度上限 |
| `turn_min_w` | — | 最小角速度，防止死区卡住 |

### 5.3 安全与贴身脱离（P82）

| 参数 | 默认 | 说明 |
|---|---|---|
| `escape_on` | 1 | 贴身脱离总开关，**必须保持 1** |
| `escape_m` | 0.60 | 人距小于此值且持续 `escape_delay_s` 触发 |
| `escape_delay_s` | 0.40 | 触发延时，滤掉瞬时抖动 |
| `escape_free_m` | 0.90 | 拉开到此距离即交回常规跟踪 |
| `escape_dur_s` | 5.0 | 兜底超时 |
| `lidar_stop_m` | — | 后方净空判定基准（退不动才触发 ESCP） |

> 关闭 `escape_on` 会重现「贴身 0.41 m 卡死 65 s」的死锁——距离环的
> 后退判据依赖「后方净空」，而人贴在后方时后方永不净空。

### 5.4 丢失与搜索

| 参数 | 默认 | 说明 |
|---|---|---|
| `lost_grace_s` | 1.1 | 无检出的宽限时间，超过才判定丢失 |
| `scan_rounds` | 2 | 允许「前往推测点」的轮次，用尽后原地扫描 |
| `goto_timeout_s` / `goto_reach_m` | 12 / 0.75 | GOTO 超时与到达判据 |
| `peek_on` | **0** | 绕视开关。实测在主场景有害（绕柱检出率 100 %→81.7 %），保持关闭 |
| `scan_seek_s` | 3.0 | 原地扫描多久后改为横移搜索 |

### 5.5 传感器（改这些要重新编译）

`vla_ws/src/vla_follow/worlds/work_area.sdf`：

| 设备 | 当前值 | 备注 |
|---|---|---|
| 4× rgbd_camera | 10 Hz，320×240，FOV 1.8 rad，0.1~12 m | 5 Hz 时方位 p90 达 40°，不满足 ±10° 需求 |
| gpu_lidar | 10 Hz，360 线，0.12~12 m | 单线、装在 0.15 m 高，看得到≠相机看得到 |
| front_camera | 10 Hz | 仅可视化 |

改完需 `colcon build` 把 sdf 同步到 `install`。

## 6. 测试

```bash
# 标准评测：120 s ×3 次，输出各指标中位数
bash tests/eval_repeat.sh 3 mytag 120

# 受控场景（demo 已在运行时）
python3 tests/test_orbit.py r1 70    # 绕柱
python3 tests/test_hide.py  h1 35    # 躲柱
python3 tests/test_stick.py s1 25    # 贴身脱离
```

产物在 `tests/out/`。

**评测方法论**：单次 in_band 波动可达 ±6 pt（同一份代码、不同轮次），
且人的轨迹在各轮次之间并不相同（逐点差最大 2.3 m），因此
**任何 <7 pt 的差异都不足以判定优劣，必须 n≥3 重复取样**；
也不要拿「同一轮次号」跨配置对比。

## 8. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报「另一个 start_demo 正在运行」 | 真有实例在跑 | `bash vla_demo/stop_demo.sh`；若为陈旧锁，脚本会自动清除 |
| 卡在「gz topics 出现」不动 | Gazebo 未起 / 上一实例残留 | 检查 `vla_ws/logs/gzsim.log`；确认 `pgrep -f "[g]z sim"` |
| `pgrep -x gz` 查不到进程 | 真实进程名是 ruby | 一律用 `pgrep -f "[g]z sim"` |
| Nav2 `Aborting bringup` | 参数缺段 / 拉了用不到的节点 | 项目已改用精简 `nav2_follow.launch.py`，不要切回 `navigation_launch.py` |
| GOTO 段机器人不动 | 桥接话题名错误 | Nav2 输出是 `/cmd_vel_smoothed`，不是 `/nav2_cmd_vel` |
| 机器人贴着人不退开 | `escape_on=0` 或后方净空误判 | 确认 `escape_on=1`；查日志「贴身 … 退不动 → 脱离」 |
| 改了代码没生效 | 用的是 install 里的副本 | 重新 `colcon build` |
| 改了 sdf 没生效 | 同上 | 重新 `colcon build`（sdf 是 data_files） |
| 语音无响应 | 模型缺失 / 声卡 | 确认 `vla_demo/vosk-model-small-cn-0.22`；可直接用 `follow_cmd.sh` 绕过语音 |
| Gazebo 窗口布局被改乱 | gz 退出时写回 gui.config | `start_demo.sh` 每次启动前调 `gz_gui_fix.py` 重写 |

### 8.1 喝水任务专项

| 现象 | 原因 | 处理 |
|---|---|---|
| 任务跑完机器人**停在桌边不动** | 交权后没人接管 | `start_drink_demo.sh` 必须带 `follower` + `cmd_mux` + 感知三个节点；只起"人/语音/喝水"三节点时 `FOLLOW` 发了没人接 |
| `DRINK ★ 失败: 倒水/捧杯阶段` | 布局改动后某段 IK 不可达 | 先跑 `python3 tools/check_ik.py`（离线体检 11 项） |
| 人走不到桌边、在桌边来回躲 | GOTO 绕障把桌子误判成挡路 | 挡路判据是"障碍到人→目标**线段**的垂距"，不是方位角；见 `person_walk._avoid_dir` |
| 人到位但杯子递不到手上 | 人没站在 `PERSON_SPOT` | 看 `pw.log` 的「已到桌边」坐标；递杯位按"人站在接水位"算，偏差 >0.12 m 就够不着 |
| 杯子在空中被"抡飞" | 交接冻结的偏移带了个大力臂 | 交接必须用 `hand_to`（换持有者、不松钉），锚点走 `PERSON_HAND_IN_ARM` |
| 松手后杯子被带跑 | 撤手时还钉着 | 松手顺序固定：张手 → 对位 → 松钉 → 撤手 |
| 杯子看上去"直接从手里拔出来" | 交还时手还没张开 | 交还顺序：机器人双手够到 → `grab` → **人双手张开** → 机器人才端走 |
| 人的手不动 / 两条手臂跟着身体一起甩 | 手 link 的摆放 | 手臂 link 原点必须放在**肩点**（`<link><pose relative_to="person_arms">`），`<joint><pose>` 会被 gz 忽略；左右两条关节轴上同向、上层发反号 |
| 手慢慢往下溜 | 子 link 继承了重力 | 手臂 link 必须逐个写 `<gravity>false</gravity>`（不继承父 link） |
| 一杯水倒完"水位没涨" | 水位没归零 | `run_drink` 开头会把 `water_joint` 归零；重复演示时必须归零才看得到水涨 |
| 端到端挂了，但不知道哪一段 | 端到端只报最终成败 | 用 `test_p86/p87/p88/p89/p96.py` 分段二分定位 |

## 9. 双端同步（Windows ↔ Linux）

远端 `/home/earl/workspace/VLA` 对应 Windows 端 `Z:\VLA`。

```bash
python3 tools/vmsync.py        # 双向同步（可用环境变量覆盖根目录）
bash tools/vmsync_run.sh
```

`VLA_LOCAL_ROOT` / `VLA_REMOTE_ROOT` 可覆盖默认路径。
