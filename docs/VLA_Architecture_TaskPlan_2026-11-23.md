## 2. 项目目标与总体架构

在 ROS 2 Jazzy + Gazebo Harmonic、移动底盘、双侧 7 自由度机械臂和灵巧手基础上，构建能够理解自然语言、感知场景、规划导航和双臂操作、判断任务完成并处理异常的 VLA 系统。

采用分层混合架构，而不是让一个模型直接控制所有底盘和关节：

| 层级 | 职责 | 主要组件 |
|---|---|---|
| L6 语言交互 | 语音识别、意图理解、指令确认 | ASR、NLU |
| L5 具身推理 | 场景语义理解、目标选择、子任务规划 | VLM/LLM |
| L4 VLA 技能策略 | 从多模态观测生成技能参数或有界动作块 | SmolVLA；OpenVLA-OFT、π0.5 对照 |
| L3 任务执行 | 阶段编排、前置条件、超时、重试、恢复 | 现有 BT/DrinkTask |
| L2 导航与操作 | 导航、精确对接、IK、轨迹、抓握、双臂协作 | Nav2、arm_kin、MCA 候选模块 |
| L1 独立安全 | 限位、碰撞、速度限制、锁止、看门狗、急停 | 独立 safety gate |
| L0 机器人 | 底盘、双臂、灵巧手、RGB-D/腕部相机 | ROS 2、Gazebo、硬件适配 |

数据流：传感器观测 → 状态估计/感知 → VLA/高层规划 → BT 授权的技能目标 → 安全校验 → 控制器 → 机器人。反馈回路由传感器估计和控制器闭环承担。

**安全边界：**
- VLA 不直接发布生产 39 路 /drink/cmd/* 关节命令。
- VLA 不得绕过关节限位、碰撞/swept-path、底盘运动权限、物理锁止、急停和物体释放门禁。
- BT 决定当前阶段是否允许执行技能；安全层可否决任何上层命令。
- 推理服务异步运行，不得阻塞底盘或关节低层控制。
- 过期动作块、无效坐标、低置信度观测、推理超时必须被拒绝。

## 3. 模型、数据和控制资产选择

### 3.1 模型路线

- **SmolVLA：首个实际基线。** 审查固定版本、权重来源、许可证、模型卡、依赖和算力；先离线回放，再进入受限仿真 sandbox，最后才考虑受门控的任务执行。
- **OpenVLA-OFT：对照基线。** 在相同观测、动作定义、场景和安全过滤下比较性能。
- **π0.5 / openpi：对照研究。** 先审查权重和运行条件；若当前算力不能运行，明确记录受限原因，不以不等价实验冒充对照结果。
- **LeRobot：数据组织、采集、回放、训练与评测工具候选。**
- **ALOHA / Mobile ALOHA：双臂遥操作、移动操作和示范数据采集参考，不要求复制硬件。**
- **MotionControlAlgorithms：低层算法候选。** DLS、S-Curve、差速运动学等继续进行模型一致性和性能验证；阻抗/导纳、QP/层级控制、CBF 在动力学、执行接口和安全论证不足前不直接上线。

### 3.2 模型与第三方治理

固定仓库 commit/tag、模型权重来源、许可证、模型卡、训练数据来源、依赖清单、硬件要求、权重 hash 和已知限制。任何许可证或来源不明的模型权重不得进入项目。记录训练配置、数据版本、模型版本和推理环境，确保可复现及回滚。

### 3.3 统一数据记录

每条轨迹至少包含：
- 语言指令、任务 ID、BT 阶段和成功/失败标签；
- 多相机 RGB/深度帧、frame_id、时间戳；
- 底盘位姿/速度、关节角/速度、手部状态；
- 动作目标、动作块、执行时间和终止标志；
- 关键对象估计位姿、置信度/协方差和数据新鲜度；
- 独立 Gazebo 真值标签（仅离线训练/评测，不送入在线策略）；
- 故障原因、碰撞/接触、抓握滑移和恢复结果。

## 4. 指标与验收口径

以下新数值是**建议初始仿真目标，不代表现有系统已达到**。阶段 A 先建立测量基线和误差预算，再确认是否冻结。

| 领域 | 指标 | 建议目标 |
|---|---|---|
| 感知 | RGB-D 有效帧率 | ≥10Hz |
| 感知 | 壶/杯/杯口/壶嘴 3D 位置误差 | ≤10mm |
| 感知 | 关键对象姿态误差 | ≤2° |
| 标定 | 相机外参误差 | 目标 ≤3mm、≤0.5° |
| 新鲜度 | 关键观测年龄 | 初始目标 ≤200ms；过期即拒绝 |
| 桌边定位 | base 相对 table 的 XY 误差 | ≤5mm |
| 桌边定位 | base yaw 误差 | ≤0.2° |
| 稳定性 | 对接稳定窗口 | 连续 ≥2s；窗口内位置波动 ≤1mm |
| 操作对准 | spout 相对 cup 目标点位置误差 | ≤5mm |
| 操作对准 | 壶嘴方向误差 | ≤1° |
| 抓握 | 抓握成功率 | ≥95%，明确统计样本 |
| 任务 | 完整任务成功率 | 可靠性阶段目标 ≥95%，报告置信区间 |
| 实时性 | 底盘/关节控制 | 沿用当前 ≥20Hz 节拍并测抖动 |
| 实时性 | VLA 推理 | 先报告 P50/P95/P99；不得阻塞低层控制 |
| 安全 | 未授权危险动作、碰撞/越限漏放 | 0 次 |
| 恢复 | 可恢复故障识别 | 100% 分类并进入有界恢复或安全停止 |

**既有硬门槛不得放宽：** 交接位置误差 ≤6mm、轴向误差 ≤0.5°；底盘锁止线速度 <0.005m/s、角速度 <0.5°/s、1 秒平移 <2mm、朝向变化 <0.5°；关节限位、碰撞/swept-path、抓握/释放与 fail-closed 检查继续有效。

桌边 base 5mm 门禁和 spout-to-cup 5mm 门禁是两个独立坐标层级，不可互相替代。Gazebo 真值只在 evaluator 中用于误差计算，不能参与在线决策。

## 5. 阶段 A｜工程基线、启动归位与低层运动可靠性

**退出条件：** 启动归位可靠；39 路命令/反馈有逐路证据；机械臂动作期间底盘满足既有物理保持门槛；安全门控无绕过；关键离线与整机回归通过。

- **P111 架构与代码基线：** 核对 TaskPlan、README、ROS packages、SDF、bridge、BT、launch、传感器 topic、Actions 和 PR；绘制模块/数据流/责任边界，区分已实现、实验、缺失。
- **P112 双臂启动归位根因修复（第一阻塞）：** 逐路追踪 ROS command、Gazebo Transport 接收、JointPositionController 响应和 joint_state；区分桥接、控制器、物理约束和伺服判据问题；保持 fail-closed。
- **P113 39 路命令与反馈契约：** 唯一发布者、更新频率、目标/实测/误差、接收计数、时间戳、断流和超时；任何关键通道缺失不得误报归位成功。
- **P114 整机模型与控制回归：** 左右臂 FK/IK、关节顺序/单位/限位、奇异邻域、轨迹连续性、速度/加速度/jerk、差速模型和双臂协调。
- **P115 底盘物理保持联合验证：** 逐关节、全 39 路、组合动作和重复试验测底盘 XY/yaw、轮速和关节响应；锁止/解锁必须有物理证据。
- **P116 控制时序和安全状态机：** use_sim_time、clock ready、传感器/命令新鲜度、启动握手、停止和恢复；故障进入明确 fail-closed 状态。

## 6. 阶段 B｜传感器感知、标定和状态估计

**退出条件：** 关键对象感知达到验证目标；坐标和时间戳一致；真值只在 evaluator；遮挡/失效能安全处理。

- **P117 传感器资产和数据契约：** 盘点前向/腕部 RGB-D、frame、内外参、深度范围、频率、同步和可用性。
- **P118 相机与手眼标定：** 建立重复标定流程、残差报告和版本化参数。
- **P119 桌面/对象三维感知：** table plane、桌沿、kettle、cup、cup rim、handle/spout、人手；输出 pose、confidence/covariance、frame_id、timestamp、有效期。
- **P120 多目标跟踪和遮挡恢复：** ID 关联、短时遮挡跟踪、重识别、丢失超时。
- **P121 多传感器状态融合：** 视觉、关节状态、IMU/里程计等实际可用观测；在线禁止 Gazebo truth。
- **P122 真值隔离评测器：** 对比传感器估计和 Gazebo truth，输出位置/姿态误差、置信区间和失败样本；增加架构/测试断言确保策略无法订阅真值。
- **P123 感知异常安全处理：** 过期、低置信度、深度空洞、TF 失败、断连时禁止抓取/倒水或安全停止。

## 7. 阶段 C｜导航、精确对接和操作空间规划

**退出条件：** 粗导航和精确对接可分别测量；table-relative 与 tool-relative 门禁独立通过；定位失效会撤销操作许可。

- **P124 导航定位基线：** Nav2 定位、地图、动态障碍和人员移动；统计成功率、路径偏差和到达时间。
- **P125 粗导航+精确对接：** Nav2 到预备区，视觉/相对定位控制器完成桌边最终对接；评估 Docking Server 或自定义插件。
- **P126 table-relative 定位门禁：** table_frame/base_link 目标、XY/yaw/速度/稳定窗口；5mm/0.2°先经误差预算确认。
- **P127 底盘锁止与操作许可联动：** 对接通过后才允许锁止和操作；漂移、锁状态丢失或定位失效撤销倒水许可。
- **P128 操作工作空间与可达性：** 根据传感器估计的壶、杯、桌沿和障碍物计算双臂可达域、碰撞余量和抓取候选。
- **P129 壶嘴—杯口几何对准：** 计算 spout_frame 到 cup_frame 的位置、方向、落点和杯口安全区域。
- **P130 多起点/多桌位泛化：** 改变桌位、角度、物体摆放、初始位姿和动态障碍。

## 8. 阶段 D｜技能执行、双臂协作和任务恢复

**退出条件：** 传统技能链路完成 DrinkTask；异常可恢复或安全停止；连续两轮完整 E2E 均 ok=true。

- **P131 技能接口标准化：** NavigateToTable、PreciseDock、Reach、Grasp、Pour、Place、Present、Handover、Receive、Retreat 的输入、前置条件和后置条件。
- **P132 抓壶/抓杯：** 视觉目标、实测掌心 FK、接触/夹持确认、滑移检测、失败撤回和重新抓取。
- **P133 倒水：** 壶嘴/杯口视觉闭环、壶姿态和水量控制；记录落点、杯内水量、溢出和杯体移动。
- **P134 放回与松手：** 保留张手→对位→解除附着/夹持→撤手顺序，释放前确认稳定。
- **P135 双臂捧杯/交接：** 双臂共同约束、相对杯轴几何、人手估计、接收状态；保留 6mm/0.5°门槛。
- **P136 失败分类与恢复 BT：** 导航、感知、抓取、倒水、放置、交接和控制异常的有界重试/回退/安全停止。
- **P137 完整 DrinkTask 集成：** 指令、导航、对接、抓取、倒水、递杯、接回、放回、撤离、恢复跟随；每阶段有证据。
- **P138 故障注入：** 丢帧、遮挡、对象移动、关节超时、锁止丢失、通信断开、仿真暂停。
- **P139 连续两轮完整 E2E：** 每轮完整任务终态、阶段、截图、日志和指标齐全。

## 9. 阶段 E｜数据集、SmolVLA 接入与模型对照

**退出条件：** SmolVLA 可复现推理；数据集可回放；对照公平；模型输出不能绕过 Action Adapter 和安全层。

- **P140 模型准入审计：** 固定 SmolVLA、OpenVLA-OFT、π0.5/openpi 版本/权重，审查许可证、模型卡、依赖、硬件和安全限制。
- **P141 LeRobot 兼容 schema：** 多相机、时间戳、语言、本体状态、动作块、BT 阶段、终止标志、成功/失败标签和场景元数据。
- **P142 示范采集：** 通过现有技能、遥操作/专家策略和仿真采集移动双臂轨迹，保留成功/失败和质量标签。
- **P143 数据治理与回放：** 完整性、同步、动作合法性、重复、覆盖和泄漏检查；按场景/初始位姿/对象实例拆分数据集。
- **P144 SmolVLA 离线推理基线：** 先做回放和 sandbox，验证 schema、延迟、资源和输出合法性，不直接接管生产机器人。
- **P145 Action Adapter：** 将动作转换为 BT 技能参数/有界末端目标，约束动作范围、时长、速度和置信度。
- **P146 SmolVLA 微调/消融：** 与专家和传统 BT/IK 比较，记录数据量、训练配置、模型 hash 和独立测试结果。
- **P147 OpenVLA-OFT 对照：** 尽量使用相同数据、场景、动作定义和安全过滤，比较成功率、延迟、泛化和资源。
- **P148 π0.5/openpi 对照：** 审核资源/许可后测试；无法运行则如实记录，不作不等价结论。
- **P149 异步推理与故障隔离：** 超时、过期动作丢弃、模型崩溃恢复和确定性安全回退。
- **P150 泛化和策略门控：** 未见桌位、物体摆放、人员位置和光照；低置信度/OOD 转传统技能或请求确认。

## 10. 阶段 F｜整机评估、可靠性与交付

**退出条件：** 独立场景可靠性数据、模型/传统策略公平对照、安全测试、可复现部署和回滚资料齐全。

- **P151 场景矩阵：** 多桌位、多初始位姿、物体摆放、遮挡、人员移动、光照和传感器故障。
- **P152 专项评测：** 感知、导航、抓握、倒水、交接分别统计误差和成功率。
- **P153 策略对照：** 同场景比较传统策略与 VLA 的成功率、恢复率、延迟、平滑性、泛化和资源。
- **P154 安全/故障注入：** 0 次未授权危险动作和碰撞/越限漏放；验证停止/回退。
- **P155 可靠性统计：** 主要场景建议至少 30 次，报告 Wilson 95% 置信区间；关键场景可扩展到 100 次。两轮 E2E 不替代统计测试。
- **P156 长时间和资源评估：** CPU/GPU/内存、推理延迟、ROS topic/service 健康、队列积压和长期漂移。
- **P157 部署与回滚：** 模型、控制器、标定参数、场景版本绑定；启动自检、健康检查和回滚。
- **P158 最终交付：** 架构、模型卡、数据说明、许可证/SBOM、部署指南、测试报告、已知限制和后续路线。

## 11. 依赖顺序和执行治理

主顺序 A→B→C→D→E→F。A 的文档治理和模型准入资料审查可并行，但不提前部署模型。B 的感知依赖 A 的传感器/时序基线；C 依赖 B 的定位；D 依赖 A/B/C；E 依赖 D 的确定性技能基线和示范数据；F 对全部阶段验收。

每个节点必须记录目标、变更文件、依赖固定版本、Actions、日志/artifact、指标、失败原因、回滚方式和状态。诊断探针、离线测试、构建成功、sandbox 成功都不能记为整机 E2E 通过。
