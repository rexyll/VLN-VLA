# 04 - 数据体系：采集、格式、标注、归一化

> [!abstract] 为什么单独成章
> VLA 项目 **60–80% 的工作量与失败原因在数据**。模型只决定"压缩数据的方式"，数据决定能力上限。本章是 [[05-训练流程]] 与 [[11-模板-VLA项目实施手册]] P1 阶段的依据。

## 1 数据金字塔

| 层 | 数据 | 规模感 | 作用 |
| --- | --- | --- | --- |
| L3 任务数据 | 目标场景遥操作演示 | 单任务 50–500 条，多任务 1k–10k+ 条 | 决定任务成败 |
| L2 跨具身机器人数据 | OXE / DROID / 自有其他产线数据 | 10 万–100 万条轨迹 | 动作先验、泛化 |
| L1 互联网数据 | 图文对、人类操作视频 | 亿级 | 语义与视觉先验（VLM 自带） |

L1 由开源 VLM 基座自带；自研项目通常从 **L3 起步，按需引入 L2 共训**。

## 2 采集方式对比

| 方式 | 成本 | 质量 | 适用 |
| --- | --- | --- | --- |
| 主从臂遥操作（leader-follower） | 中（双臂硬件） | 高、最主流 | 单/双臂操作 |
| VR 遥操作 | 中 | 高、可采移动/全身 | 人形、移动操作 |
| 手持夹爪（GELLO / UMI 类便携设备） | 低 | 高、场景自由 | 快速多场景采集 |
| SpaceMouse / 键盘 | 低 | 中（慢、抖） | 原型验证 |
| 仿真合成（Isaac/MuJoCo + 脚本专家） | 低 | 看实现 | 数据增广、危险场景 |
| 人类视频（无动作标签） | 低 | 无动作 | 只能做预训练/世界模型 |

> [!tip] 采集硬件预算参考
> LeRobot SO-101 主从臂全套约千元级，是教学与原型的最低成本方案；工业级建议主从臂 + 全局/腕部双机位 + 硬件时间同步。

## 3 数据格式标准：LeRobot v2.x（推荐默认）

核心字段（parquet + mp4，每 episode 分片）：

| 字段 | 含义 | 易错点 |
| --- | --- | --- |
| `observation.images.<cam>` | 各相机视频流 | 训练端解码分辨率必须与部署端一致 |
| `observation.state` | 本体感知向量 | 各维含义顺序必须写进元数据文档 |
| `action` | 动作向量 | 同上；且是"目标量"还是"增量"必须注明 |
| `timestamp` | 帧时间戳 | 与动作的因果对齐（见 [[09-易错知识点]]） |
| `episode_index` / `frame_index` / `index` | 索引 | 转换脚本必须重算 |
| `task_index` + `tasks.jsonl` | 任务→语言指令 | 指令规范见 §5 |

其他格式：RLDS/TFDS（OXE 生态）、HDF5（robomimic/ACT）。**自建项目统一收敛到 LeRobot 格式**，转换脚本示例：

```python
# 任意自有数据 → LeRobot v2 的最小骨架（伪代码，字段名以官方文档为准）
from lerobot.common.datasets.le_robot_dataset import LeRobotDataset  # 版本不同 API 有差异
# 每帧写入: {timestamp, observation.state: (n_state,), action: (n_action,),
#           observation.images.cam_global: frame_rgb_uint8, episode_index, task_index}
# 同时维护 episodes.jsonl / tasks.jsonl / info.json（含 fps、特征维度与视频编码）
```

> [!warning] 格式转换是事故高发区
> 三个必查项：① fps 是否真实（采集端丢帧会导致时间轴错位）；② `action` 的坐标系/单位是否写了元数据；③ 视频压缩质量是否与部署相机流一致（PNG vs 高压缩 H.264 会造成"训练清晰、部署糊"的域差）。

## 4 归一化：小事出大事

不同机器人、不同任务的取值范围差异巨大，训练前必须归一化；OXE/RT 系惯例是 **分位数归一化 q01/q99**：

```python
import numpy as np, json

def fit_norm_stats(actions: np.ndarray) -> dict:
    """actions: (N, dim) 全训练集动作拼接。分位数统计对离群值稳健。"""
    q01, q99 = np.quantile(actions, 0.01, axis=0), np.quantile(actions, 0.99, axis=0)
    return {"q01": q01.tolist(), "q99": q99.tolist(), "dim": actions.shape[1]}

def normalize(a, stats):   # → [-1, 1]
    a = np.clip(a, stats["q01"], stats["q99"])          # 先裁剪再缩放
    return 2 * (a - stats["q01"]) / (np.array(stats["q99"]) - stats["q01"] + 1e-8) - 1

def unnormalize(a, stats):  # 推理端还原，同样要 clip
    q01, q99 = np.array(stats["q01"]), np.array(stats["q99"])
    return np.clip(q01 + (a + 1) / 2 * (q99 - q01), q01, q99)
```

> [!danger] 归一化统计是模型资产的一部分
> `q01/q99` 必须**随 checkpoint 一起保存、随模型一起部署**。训练与部署用了不同统计量 = 模型输出全部错位，且 loss 看不出来。这是 [[09-易错知识点]] 第一大坑。

## 5 语言标注规范（模板）

- 每条演示配 1 条主指令 + 建议 2–3 条同义改写（"把杯子放到架子上" / "将杯子摆上架" / "pick up the cup and place it on the shelf"）。
- 指令描述**目标状态**而非动作过程（"把杯子放到架子上" 而非 "移动手臂向上 30 度"）。
- 命名规范：物体用稳定名称，颜色/位置词与场景一致；多语言项目定一种主语言+映射表。
- 失败演示：不要直接删——打 `is_failure` 标签保留（可用于错误恢复训练与评估负例）。

## 6 数据量经验估算

| 目标 | 单任务演示量（经验） |
| --- | --- |
| 固定布局抓放，原型验证 | 30–50 |
| 有扰动的一般任务（位姿随机） | 100–300 |
| 精细操作/双臂协同 | 300–1000+ |
| 跨场景泛化（新背景/新物体实例） | 1000+ 且必须**多场景采集** |
| 在 7B VLA 上 LoRA 微调一个新任务 | 常见 50–500 条起，配合增广 |

多样性比数量更重要：位姿、物体实例、光照、背景、干扰物都要**有计划地覆盖**（写进 [[11-模板-VLA项目实施手册]] 的数据计划卡）。

## 7 质量检查清单（QC）

- [ ] 时间戳：相机帧与动作帧因果对齐，无丢帧/重复帧
- [ ] 每条演示独立成功（脚本/人工抽检 10%）
- [ ] 动作无异常跳变（可视化关节/末端轨迹曲线）
- [ ] 图像无黑帧/过曝/失焦；多机位同步误差 < 半个控制周期
- [ ] 归一化统计已计算并持久化
- [ ] 指令标注符合 §5 规范；task_index 与 tasks 文件一致
- [ ] train/val 划分按 episode 划分，无同场景同位姿泄漏
- [ ] 数据卡（datasheet）成文：来源、设备、时间、负责人、已知缺陷

## 8 数据增强

| 增强 | 安全性 | 说明 |
| --- | --- | --- |
| 颜色抖动 / 亮度对比度 | ✅ 安全 | 缓解光照过拟合 |
| 随机裁剪（小幅） | ✅ 安全 | 注意会轻微改变像素-空间映射，幅度要小 |
| 时间裁剪/加速比 0.9–1.1 | ✅ 安全 | 提升时间鲁棒性 |
| 随机擦除小区域 | ⚠️ 谨慎 | 模拟遮挡，别擦到目标物体 |
| 空间翻转/旋转 | ❌ 慎用 | 会破坏相机几何与左右手约定（除非对称任务且同步翻转动作坐标系） |
| 生成式增广（换背景） | ⚠️ 谨慎 | 需验证动作标签一致性 |
