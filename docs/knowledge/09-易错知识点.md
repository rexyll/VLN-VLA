# 09 - 易错知识点（避坑手册）

> [!danger] 使用方式
> 训练前通读一遍；现场出问题时按类别检索。每条格式：**坑 → 现象 → 预防**。本手册来自 VLA/模仿学习项目的高频事故，代码仓库 `code/` 已按正确写法实现其中大部分。

## 1 归一化与统计量 ⭐最高频

| 坑 | 现象 | 预防 |
| --- | --- | --- |
| 训练与部署用不同归一化统计 | loss 正常、真机动作方向/幅度错乱 | q01/q99 随 checkpoint 归档并版本化（[[04-数据体系]] §4） |
| 推理端忘做 clip | 偶发极端动作、飞车 | unnormalize 内置 clip（参考 `dataset.unnormalize`） |
| 统计量含失败/异常离群值 | 正常动作被压到极小范围 | 分位数而非 min-max；训练前看动作分布直方图 |
| 新旧数据混合后未重算统计 | 迭代后成功率莫名下降 | 数据集每次变更 → 重算 → 新版本号 |
| 状态归一化约定漂移（像素 vs 米，/32 vs /16） | "模型在别人电脑上就不行" | 状态约定与动作约定同等对待，写进元数据（`server.py` 有注释） |

## 2 坐标系 / 单位 / 动作语义

| 坑 | 现象 | 预防 |
| --- | --- | --- |
| 弧度 vs 角度混用 | 小任务能跑，大幅动作抽搐 | 元数据写明单位；接入时断言量级 |
| EEF delta 坐标系搞错（base vs camera vs world） | "指令向左、机器人向右" | 选型时就定死并写文档（[[03-架构与技术选型]]）；可视化验证 |
| 旋转增量用欧拉角直接相加 | 姿态发散、翻转 | 旋转用四元数/轴角合成（`deploy_openvla.py` 注释） |
| 四元数顺序 wxyz vs xyzw | 仿真到真机姿态全错 | 转换函数单一出口 + 单元测试 |
| gripper 语义反转（0=开还是关） | 抓取瞬间张开，现场事故 | 接入前用空跑验证；元数据成文 |
| 左右手/镜像约定 | 双臂对称任务镜像失败 | 数据卡写明各维含义；抽帧可视化 |

## 3 图像与相机

| 坑 | 现象 | 预防 |
| --- | --- | --- |
| BGR vs RGB（OpenCV 读取） | 颜色相关的指令全部失效 | 统一 RGB 单一出口 |
| resize 拉伸 vs letterbox 改变纵横比 | 精度差、位置系统性偏移 | 训练/部署同一预处理函数 |
| 训练用清晰帧、部署用高压缩流 | "离线好、上线糊" | 视频编码参数与部署一致（[[04-数据体系]] §3） |
| 腕部相机朝向不同导致语义镜像 | 换臂位后策略失效 | 相机安装位姿纳入数据卡；增广覆盖 |
| 相机参数（曝光/白平衡）自动模式 | 光线变化时策略漂移 | 锁定曝光/白平衡；光照增广 |
| 深度相机对反光/透明物体失效 | 特定物体必失败 | 改全局 RGB + 腕部视角（附录 A §5） |

## 4 时间同步与因果对齐 ⭐隐蔽

| 坑 | 现象 | 预防 |
| --- | --- | --- |
| 观测-动作因果错位（用"导致当前状态的动作"训练） | 策略整体滞后一步，动作"追着跑" | state[t]=执行前观测、action[t]=从它出发的动作（`env_synth.py` 注释） |
| 相机帧与状态时间戳不同步 | 高速运动下抖动、目标附近振荡 | 硬件触发/PTP 同步；对齐误差 < 半个控制周期 |
| 采集丢帧后时间轴错位 | 数据集 fps 名不副实 | 转换脚本校验时间戳单调性与间隔 |
| chunk 执行期间观测过旧 | 开环段漂移 | receding horizon 或缩短 chunk（[[06-部署与推理]] §3） |

## 5 数据质量与泄漏

| 坑 | 现象 | 预防 |
| --- | --- | --- |
| 同场景同位姿跨 train/val | 离线指标虚高，上线崩 | 按 episode 划分；划分键=场景/位姿批次 |
| 遥操作抖动演示直接进训练 | 策略天生抖动 | 采集端稳、或轨迹平滑/重采样 |
| 指令标注单一（同一句话 × N） | 换个说法就失效 | 同义改写规范（[[04-数据体系]] §5） |
| 失败演示一律删除 | 不会从错误恢复；评估缺负例 | 打标签保留（is_failure） |
| 多任务混合比例失衡 | 大任务吞小任务 | 配比写入实验卡并消融 |
| 成功判据在数据与评估间不一致 | "训练成功率高、验收不通过" | 全项目唯一定义（模板 P0 卡） |

## 6 语言标注与提示模板

| 坑 | 现象 | 预防 |
| --- | --- | --- |
| 训练/部署 prompt 模板差一个空格 | 语言泛化直接失效 | 模板字符串入库随模型发布（`PROMPT_TEMPLATE` 常量） |
| 大小写/标点/中英混排不一致 | 同上 | 推理端做与训练相同的规范化 |
| 指令描述动作过程而非目标状态 | 策略学成"回放轨迹" | 标注规范："放到架子上"而非"抬起手臂" |

## 7 训练过程

| 坑 | 现象 | 预防 |
| --- | --- | --- |
| 学习率过大毁掉 VLM 先验 | 语言理解退化、loss 先降后崩 | LoRA 起步；val 加语言探针任务 |
| 只盯 loss 不做 rollout | 选了"loss 最好、真机最差"的 checkpoint | top-k checkpoint 全部 rollout（[[05-训练流程]] §5） |
| 小数据过拟合后 loss 继续降 | 误判仍在进步 | 每 epoch 做 val + 定期真机抽测 |
| diffusion/flow 采样步数 train≠test | 评估结果不可复现 | 采样器与步数写进配置 |
| fp16 溢出 NaN | 训练中断 | bf16；梯度裁剪 |
| 忘记固定 seed/数据版本 | 实验不可复现 | 实验卡 + 一键复现脚本 |
| LoRA 只挂注意力模块 | 复杂动作学不动 | attention+MLP（参考 `finetune_openvla_lora.py`） |

## 8 动作块与执行

| 坑 | 现象 | 预防 |
| --- | --- | --- |
| chunk 全开环执行 H=50 | 长漂移、撞偏 | receding horizon（`robot_loop.py` 默认） |
| temporal ensemble 权重错 | 抖动或迟钝 | ACT 论文指数权重；先仿真验证 |
| 控制频率不匹配（训练 5Hz、执行 20Hz 不插值） | 速度整体偏快/慢 | 执行端插值或对齐频率 |
| chunk 切换瞬间跳变 | 每隔 H 步顿挫 | 重叠区融合/低通（代价是响应性） |
| 平滑滤波过强 | 轨迹切角、漏抓 | 滤波参数当超参消融 |

## 9 评估方法

| 坑 | 现象 | 预防 |
| --- | --- | --- |
| 只测"最好看的几个条件" | 汇报成功率虚高 | 评估矩阵全覆盖（[[10-评估与安全]]） |
| 每条件 <20 次就下结论 | 噪声当信号 | Wilson 置信区间（`evaluate.wilson_ci`） |
| 仿真成功率直接外推真机 | 严重高估 | 仿真只做回归测试，定版靠真机 |
| cherry-pick checkpoint | 复现不了汇报数字 | 评估脚本+版本归档 |
| 无安全回归项 | 改版后引入危险行为 | 评估矩阵含安全用例（急停/越界/遮挡） |

## 10 部署运维与安全

| 坑 | 现象 | 预防 |
| --- | --- | --- |
| 只更新模型不更新统计量/模板 | "同一个版本却行为不同" | 四件套同版本发布（[[06-部署与推理]] §7） |
| GPU 热节流 | 周期性卡顿、掉 chunk | 温度遥测 + 降频兜底 + 看门狗 |
| 观测含 NaN 直接喂模型 | 无人机行为 | 输入校验（`SafetyLayer` 示范） |
| 急停依赖软件链路 | 程序卡死 = 停不下来 | 硬件急停独立于一切软件 |
| 日志含车间人脸/屏幕 | 合规风险 | 采集端脱敏（附录 A §14） |
| 影子模式跳过直接全量 | 新模型首日大事故 | 影子 → 单机 → 灰度（图 2） |

## 11 认知误区（写给决策者）

- ❌「VLA 万能」：长时程组合、精确力控、透明物体仍是短板，混合架构是主流。
- ❌「数据越多越好」：微调场景质量与多样性 > 数量；脏数据直接教会模型坏习惯。
- ❌「端到端取代一切」：低层控制、安全层、标定、时间同步依然是传统工程，且不可或缺。
- ❌「语义涌现=理解」：是统计泛化，超分布仍会自信地犯错——所以安全层与评估矩阵永远在。

## 12 本库代码里真实踩过的坑（v3 修复实录）

以下是 MiniVLA 教学代码在真实验证中抓到并修复的问题，每条都在 `code/` 中留有正确示范，可作为排障时的参照样本：

| # | 坑 | 现象 | 修复 |
| --- | --- | --- | --- |
| 1 | **记录动作 ≠ 执行动作** | 专家"先裁剪后加噪声"→ 训练目标最大 41.5px/s 超出物理上限 40 | 先加噪声再裁剪：记录值=执行值，单一代码路径（`env_synth.expert_action`） |
| 2 | **零动作长尾主导数据** | 成功后帧占 60%，模型学成"输出趋零"：方向余弦 0.19，闭环 0% 成功率 | 回合在成功后截断少量"停止"帧（`tlen` 字段） |
| 3 | **tanh 输出 + 饱和目标（±1）** | 边界处梯度消失，动作推不到物理幅度 | 线性头输出，范围由 unnormalize 端裁剪保证 |
| 4 | **从零学亚像素视觉定位太慢** | 2000 步优化后方向余弦仍≈0.2 | 辅助密集监督头：训练期同时预测目标位置，推理不用（dense supervision） |
| 5 | **观测-动作因果错位** | 策略整体滞后一步（数据生成时用"导致当前状态的动作"配对） | state[t]=执行前观测、action[t]=从它出发的动作（`env_synth.gen_episode` 注释） |
| 6 | **tokenizer mask 补齐顺序** | 先补 ids 再算补齐量 → mask 长度=真实词数，训练直接崩溃 | 先算 n_pad 再分别补齐（`dataset.encode_text`） |
| 7 | **末端停止行为泛化** | 成功后零动作尾帧教会模型“靠近目标→停车”，边界外推到 8–14px，闭环成功率 10% | 辅助头预测目标 + 显式误差信号(aux-state)接入动作头，消除“停/继续”歧义（`model.py`）；配合去掉尾帧（`make_notail.py`） |
| 8 | **pkill 模式自匹配** | `pkill -f collect_gazebo ...` 把包含同串的外层命令/会话一起杀掉（RC=-1 无输出） | pkill 只放进独立脚本文件，使命令行不含模式串 |
| 9 | **nohup 后台任务挂住 SSH 通道** | 远程 `nohup cmd > log &` 未重定向 stdin，ssh 等待所有 fd 关闭导致通道超时 | 加 `< /dev/null`，或用独立脚本启动 |
| 10 | **单客户端串行桥接** | 长连接（采集器）占住 accept 队列，探测/监控连接全部超时，误判为服务崩溃 | 每客户端一线程 accept（`vla_bridge.cpp` ServerLoop） |

> [!note] 排障方法论
> 定位 1–4 靠的是同一个闭环诊断脚本思路：**① 训练样本单步预测精度（方向余弦）→ ② 训练回合闭环重放 → ③ 新种子 rollout**。三步分别隔离"输入管线错位 / 闭环发散 / 泛化不足"。见 `debug_diag.py` 式的三段探针。
