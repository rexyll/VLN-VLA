# 总体架构与流程

## 1. 系统目标

人在 12.3 m × 12.3 m 场地内随机走动、转向、停顿、后退。机器人须：

1. 随时跟紧，把人保持在 **front 相机视野中间，左右摆动 ≤10°**；
2. 人不在 front 时优先调整朝向；
3. 完全离开 4 向视野时，按最后 10 张图像推测位置并前往，到达后抓拍重找；
4. 途中人重现立即调整朝向；
5. 全程优先避障，不允许物理接触（接触半径 0.44 m = 裙摆 0.26 + 车体 0.18）。

另外在跟随之上叠了**双臂操作任务**（喝水）：机器人装 2 条 7 轴机械臂 + 2 只
Shadow Hand，场景里有一张桌子、一把水壶、一个带柄水杯。人说一句"我要喝水"
之后，机器人完成倒水、双手捧杯递出（杯柄朝人）、接回、放回原位，最后撤离
桌边并把底盘**交还给跟随**，继续跟人走。详见 §8。

## 2. 分层架构

```
┌─ 仿真层  Gazebo Harmonic ────────────────────────────────────┐
│  work_area.sdf │ 4× rgbd (10Hz) │ gpu_lidar │ person_walk    │
└────────────────────────┬─────────────────────────────────────┘
                         │ 图像 / 深度 / 真值位姿
┌─ 感知层 ───────────────┴─────────────────────────────────────┐
│  person_vision（人在哪） │ depth_percept（障碍多远） │ gt_tf（定位）│
└────────────────────────┬─────────────────────────────────────┘
┌─ 指令层 ───────────────┼─────────────────────────────────────┐
│  voice_trigger → voice_node（Vosk）→ /robot/command           │
└────────────────────────┬─────────────────────────────────────┘
┌─ 决策层 ───────────────┴─────────────────────────────────────┐
│  follower 状态机：TRACK / GOTO / SCAN / PEEK / ESCP（+ALIGN） │
└────────────────────────┬─────────────────────────────────────┘
┌─ 执行层 ───────────────┴─────────────────────────────────────┐
│  cmd_mux（仲裁 + 硬闸）  │  Nav2（仅 GOTO 段接管）             │
└────────────────────────┬─────────────────────────────────────┘
┌─ 输出层 ───────────────┴─────────────────────────────────────┐
│  /robot/cmd_vel（唯一底盘写入口） │ gz_viz（轨迹/路径可视化）  │
└──────────────────────────────────────────────────────────────┘

┌─ 操作层（喝水任务，P84~P92）─────────────────────────────────┐
│  drink_task（业务编排：9 阶段状态机 + 运动原语库）            │
│      │  37 路 /drink/cmd/*（20Hz）   │  /drink/carry（抓取）  │
│      ▼                                ▼                       │
│  gz 关节控制器                GraspCarry 世界内 C++ 插件       │
│  （双臂+十指）                （抓握附着 / 位姿钉住 / 滑动副） │
└────────────────────────┬─────────────────────────────────────┘
                         │ 任务收尾发 /robot/command {"FOLLOW"}
                         └──→ 交还给上面的决策层（follower）
```

**操作层与跟随层是分时复用同一个底盘的**：`DRINK` 一到，follower 停车让权、
cmd_mux 上 300 s 锁，底盘完全归 `drink_task`（递杯位按真值 base 现算，车一动
就偏）；任务收尾后 `drink_task` 发 `FOLLOW`，follower 恢复跟随、cmd_mux 解锁。

## 3. 模块职责

| 模块 | 层 | 职责 |
|---|---|---|
| `person_walk` | 仿真 | 驱动 Gazebo 里的「人」行走；`PW_SEED` 随机或 `PW_REPLAY` 回放 |
| `person_vision` | 感知 | 4 路 RGB-D：HSV 暗色先验 + 面积/宽高比/深度/几何一致性四道过滤 → 目标方位与距离 |
| `depth_percept` | 感知 | 4 向深度分 5 扇区取 5 % 分位数 → 各向最近障碍距离 |
| `gt_tf` | 感知 | Gazebo 真值 → TF `map→odom→base_link`（GPU 激光在本机无效，AMCL 不可用） |
| `voice_trigger` | 指令 | 定时播放真人语音并触发识别 |
| `voice_node` | 指令 | Vosk 离线中文识别，解析出 `FOLLOW`/`STOP` 与距离 |
| `follower` | 决策 | 状态机 + 距离 PID + 人速前馈 + 绕障 + 安全闸；GOTO 段下发 Nav2 目标 |
| `cmd_mux` | 执行 | 自研速度 vs Nav2 速度择路；近距硬闸（L4 只加强不削弱） |
| `gz_viz` | 输出 | 预建静态小球 + set_pose，画实际轨迹与 Nav2 规划路径 |
| `gen_map` | 工具 | 由已知几何生成 Nav2 静态地图（arena.pgm/yaml），启动前调用 |
| `drink_task` | 操作 | 喝水任务编排：9 阶段状态机 + 运动原语库（`reach`/`place_held`/`put_down`/`turn_base`/`pour_into_cup`/`drive_to`…）；37 路关节指令与抓取附着指令的**唯一发布者** |
| `GraspCarry`（gz 插件） | 操作 | 世界内 C++ 系统插件。每 tick 把"物体该在哪"用 `SetWorldPoseCmd` 钉住（抓握附着），并用 `JointPositionReset` 运动学驱动壶/杯上的滑动副。纯执行器，不含运动学 |
| `scene_layout.py` | 工具 | 桌子/水壶/水杯/服务位/接水位/撤离位的**唯一坐标真源**，SDF 生成、桥接配置、运行时三处共用 |
| `gen_drink_scene.py` | 工具 | 由 `scene_layout.py` 生成喝水场景 SDF |
| `check_ik.py` | 工具 | 离线可达性体检（11 项），改布局后先跑它 |

## 5. 状态机

主状态存在 `follower._track`，`ALIGN` 是 TRACK 内部的子行为
（`_aligning` 标志，方位超出 `aim_band_deg` 时原地纯旋转）。

| 转换 | 条件 |
|---|---|
| → TRACK | 收到 FOLLOW 指令；或任意状态下视觉重新捕获（ESCP 期间豁免，避免乒乓） |
| TRACK ↔ ALIGN | 方位偏差 >15° 进入对正，回到带内退出 |
| TRACK → ESCP | 人距 <0.60 m 持续 0.40 s **且** 后方净空不足（退不动） |
| ESCP → TRACK | 人距 >0.90 m 持续 0.30 s，或超时 5.0 s |
| TRACK → GOTO | 丢失 >`lost_grace_s`，有视觉历史，扫描轮次未用尽 → Nav2 前往推测点 |
| TRACK → SCAN | 丢失且无视觉历史，或扫描轮次用尽 → 原地扫描 |
| GOTO/SCAN → PEEK | 丢失但视线被障碍挡住（`peek_on=1` 时才启用；**当前默认关闭**） |

> PEEK 实测在主场景有害：绕柱检出率 100 % → 81.7 %、丢失 0 → 24 次。
> 原因是正反馈——绕柱时人周期性被挡 → 绕视把机器人往侧向带走 → 更看不见。
> 判定「绕视是否有收益」必须走 n≥3 重复取样，单轮对比不作数。

## 6. 调用链（一次跟随）

```
voice_node（Vosk 识别）
   → /robot/command {"action":"FOLLOW","distance":1.0}
follower._cmd_cb（解析，置 target_d）
   → 进入 TRACK
person_vision（每帧：暗色先验 + 几何一致性）
   → /perception/person {bearing, dist, cam}
follower 控制环（20 Hz：距离 PID + 人速前馈 + 绕障 + 转向仲裁 + 安全闸）
   → /follower_cmd_vel
cmd_mux（nav2_active 仲裁 + 近距硬闸）
   → /robot/cmd_vel
Gazebo 底盘执行 → 位姿变化 → 相机重新成像（闭环回到 person_vision）
```

安全闸是**串联的最后一道**，位于 cmd_mux：按行进方向判定，正朝前/后走且
该向深度 <0.28 m 就清零线速度；任意方向 <0.15 m 直接停；转向不限制
（留出脱困能力）。

## 7. 关键设计决策

| 决策 | 原因 |
|---|---|
| 真值定位走 gz `dynamic_pose/info`，不用 `/robot/odom` | odom 系在 `set_pose` 后不重置 |
| 用 gz-transport 直连，不全部走 ros_gz_bridge | 图像/深度量大，桥接引入额外延迟与丢帧 |
| 遮挡判定用几何 OBB/Slab，不靠雷达 | 雷达只有单线且装在 0.15 m 高，「雷达看得到」不等于「相机看得到」 |
| 4 路 rgbd 提到 10 Hz | 5 Hz 时绕柱场景方位 p90 达 40°，超出 ±10° 需求；10 Hz 降到 3.3° |
| Nav2 只接管 GOTO 段 | 自研控制器在对正/跟踪上更可控；Nav2 负责远距离导航 |
| 速度写入口唯一（cmd_mux） | 避免自研与 Nav2 同时下发 `/cmd_vel` 打架 |
| 贴身时不再试图后退，改为转向绕出（ESCP） | 人贴在后方时「后方净空」永远不成立，距离环的后退判据永不触发 → 死锁 |

## 8. 喝水任务（操作层）

### 8.1 阶段链

```
IDLE
 └ 收到 DRINK
PREPARE    抓壶 → 倾斜倒水（水位上升、水柱可见）→ 壶放回原位 → 双手捧杯 → 转身面向人
PRESENT    双掌前伸到递杯位（= 人身前 0.30 m 的手，杯柄朝人）
           → 人**双手张开**等着接（手心间距 184 → 345 mm，0.8 s 斜坡）
HANDOVER   人**双手合拢捧住**（345 → 184 mm，正好贴住杯壁）
           → 把手里的杯子"换持有者"交到人的手上 → 张手 → 双臂收 home
PERSON_DRINK  人举杯（person_arm_joint）→ 停一会儿 → 放下
TAKE_BACK  机器人双手够到杯子 → 左手 grab 当主手
           → 人**双手张开交还**（184 → 345 mm）→ 机器人端走
           → 人收手 → 右手 hand_onto 贴对侧
PUT_BACK   转回桌前 → 摆正底盘 → 杯子放回原位 → 松手
RETREAT    双臂收 home → 真开出去撤离桌边 1.15 m（不用 teleport，画面要看得见）
HANDBACK   发 /robot/command {"action":"FOLLOW"}：follower 恢复跟随 + cmd_mux 解锁
DONE → IDLE
```

`/drink/state` 在**每次状态变化时就广播一条**（不是等 5 s 心跳），端到端脚本
靠它抓阶段截图。

### 8.2 调用链（一次倒水）

```
person_walk（走到 PERSON_SPOT、面向机器人）
   → /voice/request "text:我要喝水"
voice_node（识别/直通解析）
   → /robot/command {"action":"DRINK","source":"text"}
follower 停车让权 + cmd_mux 上 300s 锁
drink_task.run_drink()
   ├─ 运动学：KDL 求解目标掌心位姿 → 7 轴关节角（arm_kin.py 唯一真源）
   ├─ 关节：39 路 /drink/cmd/*  @20Hz  → gz 关节控制器
   │        （臂 14 + 手 20 + jet/water 2 + 人的肩 1 + 人的双臂 2）
   ├─ 附着：/drink/carry "grab cup x y z qx qy qz qw" → GraspCarry 插件
   │        （之后每 1ms 由插件把物体钉在掌心 @冻结偏移）
   └─ 真值：/world/<w>/dynamic_pose/info  → 每拍刷新 base，目标按 base 现算
```

### 8.3 三条硬约束（改这块代码前必读）

1. **抓握不是物理接触，是位姿钉住。** 上位机按实测掌心位姿算出"物体该在哪"，
   每 tick 由世界内插件写 `SetWorldPoseCmd`。附着/脱离都走 `grab`/`release`，
   换持有者（机器人手 → 人的手）走 `hand_to`，中间的交接不能松钉再抓
   （松了就掉）。
2. **送位一律对物体真值闭环，不送"名义抓取位"。** 抓握瞬间实测掌心与名义位姿
   差几毫米/一两度，会经偏移力臂放大成十几毫米。
3. **松手顺序固定：张手 → 对位 → 松钉 → 撤手。** 保留钉住就撤手会把物体一起
   拖走（实测偏差 98~127 mm）。
4. **杯子钉在肩架上，不钉在手上（P96）。** 人的两条手臂是各自的 link，但
   `GraspCarry` 只允许一个宿主 —— 钉到手上就得两只手各拽一半。钉点始终是
   `person_arms` 的 `PERSON_HAND_IN_ARM`（在肩架系里是固定点），手只负责
   "合拢到杯面上"这一层。代价是手到杯轴的间距里含着机器人的递杯误差
   （实测 11~23 mm），判据按这个量给带宽，别指望它恒等于相切值。

### 8.4 交权时序（P92）

```
  t0    TAKE_BACK 完成 → drink_task 发 /person/command {"DRINK_DONE"}
        person_walk 收到 → LEAVE 状态走出桌边 → 恢复随机活动
  t0+   PUT_BACK  机器人转回桌前、放回杯子（与人并行，互不等待）
  t1    RETREAT   双臂 home → drive_to 真开出去到 SERVE_RETREAT_XY（距桌心 2.0 m）
  t2    HANDBACK  发 FOLLOW（连发 3 帧：单向话题发现期会丢消息）
        ├─ follower：IDLE → FOLLOW，恢复跟随
        └─ cmd_mux：解 300 s 喝水锁，速度重新放行
  t2+   人继续随机走，机器人跟上去
```

撤离点选在距桌心 2.0 m，是为了让 follower 一接手就在桌子膨胀圈
（外接圆 0.62 + INFLATE 0.56 = 1.18 m）之外，不会先跟桌子较劲。

### 8.5 主循环：跟随常驻 + 喝水随机触发（P95）

喝水不再是"外部喂一条指令就跑一次"，而是**人的随机自发行为**；机器人平时
一直在跟随，只在被触发时让位去做那套辅助动作，做完交还底盘继续跟。

```
        ┌──────────── follower：跟随（常驻）─────────────┐
        │                                                │
   人在随机活动 ──(冷却过了)──→ person_walk._maybe_drink() │
        │                          │                     │
        │                     走 GOTO 到接水位            │
        │                     （每次站偏 ±0.06m / ±8°）    │
        │                          ↓                     │
        │                   说"我要喝水"                  │
        │                          ↓                     │
        │            voice_node → /robot/command DRINK    │
        │                          ↓                     │
        └──── follower 停车让权 + cmd_mux 上锁 ───────────┘
                                   ↓
                        drink_task.run_drink()（§8.1 九个阶段）
                                   ↓
                        HANDBACK 发 FOLLOW → 回到跟随（常驻）
```

三条时序上的关键约束：

1. **冷却从"喝完"起算，不是从"决定去喝"起算。** 机器人接回杯子后还有放回 +
   撤离 + 交权约 60 s，而人走开只要十几秒。若冷却从"决定去喝"起算，会出现
   "人已经站到桌边开口了、机器人还在撤离"：第二条 `DRINK` 进了 `drink_task`
   的队列，随后撤离结束发的 `FOLLOW` 会把这条新请求的 `cmd_mux` 喝水锁一起
   解掉，第二轮任务期间 follower 就来抢底盘。
2. **`ESCAPE` 状态不触发喝水。** 那是人正在脱离障碍/贴身状态，中途改成"去
   喝水"会和绕障逻辑互相抢方向盘。
3. **手动下发与随机自发走同一条路** `_start_drink()`，行为完全一致，只在日志
   里写明是谁发起的（"自己想" / "收到"）。演示想立刻看一次就用
   `send_person_cmd.sh drink`；跑验收脚本时设 `PW_AUTO_DRINK=0` 关掉自发行为，
   否则它会和验收下发的指令打架。

### 8.6 人的双手（P96）

原来 `person_arms` 是一条把两条手臂焊在一起的刚体、只有一条俯仰关节，两只手
永远相距 170 mm —— "双手接杯"只是把杯子钉进那个缝里，画面上手一动不动。

```
skirt（人形本体、差速驱动）
  └─ person_arms       肩架：两颗肩球 + 俯仰关节（举杯/仰杯）
       │                ★ 杯子钉点在这里（PERSON_HAND_IN_ARM = (0.20,0,-0.02)）
       ├─ person_arm_l  肩点竖轴外展 revolute，轴 (0,0,1)  手心 + 上臂
       └─ person_arm_r  肩点竖轴外展 revolute，轴 (0,0,1)  手心 + 上臂
```

两条关节的轴**都写 (0,0,1)**，上层对右侧发**反号**值（左 +v / 右 −v）。写在
SDF 里用 `(0,0,-1)` 也能让两侧同义，但那要靠 gz 真的尊重负轴，而人的关节
**不在 `/drink/joint_state` 里**（那条桥的是 `robot` 模型的关节），读不回来、
只能从画面上看 —— 排查成本太高。上层反号是纯 Python，一眼可验。

| 幅度 | 手心间距 | 用途 |
|---|---|---|
| `PERSON_HAND_CLOSE = 0.035 rad` | **184 mm** | 合拢：手到杯轴正好 92 mm = 杯 R40 + 手掌 R52（相切） |
| `PERSON_HAND_OPEN = 0.42 rad` | **345 mm** | 张开：杯子两侧各留 81 mm，让杯子进得来 |

三条不能破的规矩：

1. **转轴落在肩点。** 靠 `<link><pose relative_to="person_arms">` 摆，不靠
   `<joint><pose>`（gz-sim 8 会忽略后者）。摆错的话手臂会绕着腰甩。
2. **子 link 逐个写 `<gravity>false</gravity>`**（不继承父 link）。手是
   0.25 kg 的轻 link，受重力时位置控制器会跟重力矩较劲，手慢慢往下溜。
3. **人先动手，机器人后动。** 接杯是"人合拢捧住 → 机器人松手"，交还是
